### 程式碼審查修復(2026-08-01,15 項發現全數處理,vitest 566 綠/typecheck 0)

**P0(會直接傷客人 / 靜默資料遺失)**
1. **停用卡被自動套用復活**:`loadOldChunksForDiff` 只濾 isOverview,過期停用卡仍在 diff 中;自動套用會把 status 寫回 indexed,**過期募資/折扣卡無聲對客人復活**,且到期日已搬到 expiredAt、排程不會再停用第二次。修法=autoapply 改用 `listChunksBySource` 一次取回含 status,disabled 卡進 diff 但命中即整源退人工(reindex/reindex-all 早有同樣護欄,自動路徑漏了)。
2. **contentHash 先寫再跑 LLM → 逾時永久遺失變更**:自動套用是整條 cron 唯一會撞閘道逾時的工作(LLM 重切+逐卡 embedding),原本 hash 已先提交,逾時會留下「卡改一半+hash 是新值」→ 下輪比對 unchanged,永遠沒人發現。修法=抽 `commitChange()`,**一律在套用之後才提交**;逾時只是下輪重跑,已套用的卡在 diff 中是 unchanged,天然冪等。

**P1**
3. 自動套用繞過 `normalizeChunkInput`/`validateChunkInput`(其他寫入路徑都有):超長/空白卡會直接寫進知識庫 → 改在 classify 內正規化+驗證,不合規整源退人工。
