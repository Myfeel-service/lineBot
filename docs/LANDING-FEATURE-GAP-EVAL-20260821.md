# 導購頁功能缺口評估（2026-08-21）

> 這是決策紀錄，寫完凍結。狀態一律看 `docs/STATUS.md`（對應編號：`C-55`〜`C-58`、`C-31` Phase 2、`G-6`、`H-15`）。
> 背景：導購頁改版（`G-19`）後，老闆要求盤點「能用但打折」與「還沒有（掛即將推出）」的功能，
> 逐項評估必要性、難度、優先順序。本報告的每一句「有／沒有」都是當日逐段讀程式碼查證的，不是印象。

## 當時看到什麼

導購頁上的宣稱分四種：真的能用（9 項，不在本報告）、能用但打折（2 項）、還沒有（5 項）、
寫在頁面上但後端擋不住（`G-2`，另案）。本報告評後兩者共 7 項。

查證中最重要的一個發現：**隱私權頁 125 行承諾「對話、客戶名單⋯你可以隨時在後台自行刪除」，
但客戶名單與對話沒有任何刪除入口**（`server/api` 全掃，只有知識庫、圖文選單這類設定物可刪）。
這不是「即將推出」的問題——頁面用的是現在式，法律上已經在承諾一件做不到的事。

## 為什麼這樣排

- **P0 的兩條共同點：便宜、而且各堵一個「說了做不到」。** 刪除權是法遵（已承諾）；
  歡迎訊息是七項裡投報比最高的（2–3 天拆掉一顆「即將推出」徽章）。
- **C-58 排 P1 不是因為不重要，是因為卡在老闆的決策不是工程。** 三條路成本差 20 倍，
  先拍板才知道要排多少人力。短期建議走③（改口徑，今天的資料就算得出來），
  中期再決定①②——③做了不浪費，將來有購買資料時「沒講過話」和「沒回購」是兩個都有用的分眾。
- **C-55 壓在 P2 只因為前提未熟**：`C-54` 還沒推上 main、沒實機收過一則。在沒驗過的
  東西上疊功能，出問題時分不清是哪層壞的。
- **C-31 Phase 2 墊底是刻意的**：它是唯一「做錯會直接弄壞客人看到的東西」的一條，
  而且要先蓋確認流地基。門面已誠實標示，不急。
