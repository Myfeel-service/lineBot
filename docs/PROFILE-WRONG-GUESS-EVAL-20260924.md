## 🔴 第四道的洞：價格帶會被切壞，然後進 AI 的設定

### 怎麼發生的

- `products` 這一欄同時裝「主打商品」與「價格帶」（欄位 label 就是「主打商品與價格帶」，`aiHint` 要模型把價格帶寫成「NT$180–1,280」這種區間）。
- 生 AI 語氣時走 `splitProducts()`（`shared/store-profile-drafts.ts:81-87`），它用 `[、,，/／]` 切。
- **價格帶的千分位逗號正好是分隔符。**

拿 repo 自己的函式跑（唯讀、純函式、沒連任何服務）：

```
輸入 : 黑豆水、養生茶包、節慶禮盒｜NT$180–1,280
切成 : ["黑豆水","養生茶包","節慶禮盒｜NT$180–1"]

輸入 : 黑豆水、養生茶包、節慶禮盒 | NT$0–7,030,300
切成 : ["黑豆水","養生茶包","節慶禮盒 | NT$0–7"]
```

再往下一步，`buildToneDraft()` 生出來的第一行（**這一段會整包覆蓋 `systemPrompt`**）：

```
你是一家零售／電商的客服助理，主要商品是黑豆水、養生茶包、節慶禮盒｜NT$0–7，客人多半是一般消費者。
```

**AI 的設定裡出現了一個叫「節慶禮盒｜NT$0–7」的商品。**

### 兩件事要分清楚

- **價格猜錯**只在網站看不出單品售價時發生（09-22 實測：MYFEEL 是募資頁，模型把募資總額當價格，抽出 NT$0–7,030,300）。`aiHint` 已經點名募資總額／贊助人數／折扣％／運費／劃線價都不算，但擋不住全部。
- **被切壞是每次都會發生**——只要價格帶有千分位逗號（180 以上就有），不管猜得對不對。

### 有沒有被接住

安全規則第 3 條寫著「價格、成分、出貨天數這類數字，只能講知識卡上寫的」，所以 AI **不應該**把那個數字報給客人。但：
- 那個殘缺字串仍然在 prompt 裡，以「商品名」的身分存在；
- 商品清單本身就錯了（第三樣商品叫「節慶禮盒｜NT$180–1」）；
- 而商家在輪廓卡上看到的是完整的「NT$180–1,280」，**看不出下游被切壞**。

## 建議

| # | 做什麼 | 為什麼 |
|---|---|---|
| ①（建議做） | **價格帶從商品那一格拆出來，自己一格** | 它是最容易猜錯的一格、又是客人最常問的事；拆開之後猜錯的價格不會污染商品名，而且可以單獨標來源、單獨改。**已畫進示意頁 v57** |
| ②（建議做） | **AI 猜的價格帶不進 `systemPrompt`** | 安全規則第 3 條本來就說「價格只能講知識卡上寫的」——那 prompt 裡本來就不該有價格。價格留在輪廓卡上給人看就好 |
| ③（補強） | `splitProducts()` 不要用 `，` 當分隔符，或至少拆之前先剝掉價格 | 就算 ①② 都做了，`products` 仍可能被商家自己打進逗號（「禮盒 A,B」）。⚠️ 這條是**防守**不是解法 |

⛔ **不建議**「按都對了就把 AI 推測全部轉成你說的」：那是把「他沒仔細看」當成「他確認過」，`profileReady` 的口徑會立刻失真。

## 還沒驗證的

- **沒有看過正式庫裡真實的 `products` 值**。上面的輸入是照欄位 `aiHint` 的規格構造的（「與價格帶」「NT$180–1,280 這種區間」），分隔符用 `｜` 與 `|` 各試一次。⚠️ 模型實際回的格式可能不同（例如用括號、用空格），但**只要含千分位逗號就會中**。要確定的話，拿一個有讀過網站的帳號把 `storeProfiles` 那一格印出來。
- 沒有量過「AI 猜價格帶」的準確率，只有 09-22 那一個失敗案例。
