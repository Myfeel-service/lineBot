**日期**：2026-08-08　**範圍**：`app/pages/admin/[workspaceId]/ai-scripts.vue`、`auto-reply.vue`、`app/assets/scss/pages/_ai-scripts.scss`
**起因**：老闆問三件事——(1)「客人答不出來時」那塊要不要改叫「其他選項」(2) 能不能有多顆按鈕 (3) 平常用不到那顆按鈕，整塊 UI 能不能更好；外加「自動回覆和客服腳本是不是完全重疊」。

## 一、三個直接問題的答案

### Q1. 改叫「其他選項」？→ **不建議**

三個理由：

1. **會跟「快速回覆」的選項撞名。** 快速回覆節點裡那幾顆按鈕本來就叫「選項」。同一頁兩個東西都叫選項，是最容易長歪的那種命名漂移。
2. **「其他選項」講的是「這個欄位是什麼」，不是「它幫客人解決什麼」。** 這塊存在的唯一理由是：客人手上根本沒有這筆資料時有路可走。名字要留住這個語意。
3. 但**現在的名字也不對**——它是一整句話當標籤用：

   ```
   標籤：客人答不出來時（選填）：多給一顆跳過按鈕，點了改走別條路
   說明：問這一題時會多這顆按鈕。例：問訂單編號附「我沒有訂單編號」，點了就跳去改問 Email。兩格都留空＝不提供跳過。
   ```

   標籤跟說明講的是同一件事，講了兩遍。標籤的工作是「命名」，說明的工作是「解釋」。

**建議命名**：標籤縮成 **「答不出來的退路」**（選填），解釋留在說明列，不重複。

### Q2. 可以有多顆按鈕嗎？→ **技術上可以，但不建議做**

現在資料結構是 `skipLabel` / `skipNext` 一組。要支援多顆，型別、引擎比對、驗證、流程圖、試跑面板五個地方都得改成陣列。

**不建議的理由**：多顆退路等於這一題已經不是開放問答、而是選單，而選單本來就有專屬節點（快速回覆）。收集節點同時擺「請打字回答」和三顆按鈕，客人不知道該打字還是該點。

**而且這個需求已經做得到**——把退路指向一個「快速回覆」步驟就好，正式站的「查詢訂單」現在就是這樣跑的：

```
收集：訂單編號  ──答得出來──→ 寫名單 → 回覆
       └─ 按「我沒有訂單編號」→ 快速回覆「方便提供 Email 嗎？」
                                    ├─ 提供 Email → 收集 email
                                    └─ 沒有 Email → 收集 姓名 → 電話
```

**要做的不是加按鈕，是把這條路寫進提示**：說明列補一句「需要給客人多個選擇？把退路指到一個『快速回覆』步驟」，並在「前往…」下拉的「接下一步」群組裡把「快速回覆」排第一。

### Q3. 平常用不到 → **預設收起來**

現在不管有沒有用到，兩個空欄位永遠佔一整塊高度，還配一句長說明。八成的收集步驟不需要它。

**改法**：沒設定時只顯示一顆文字鈕 **`＋ 加一條退路（客人答不出來時）`**；點了才展開兩個欄位。已經設定時直接展開，右側保留「✕ 移除」。

**再進一步（把後端剛做好的檢查接到編輯器）**：當這一題的答案格式是「純數字／英文＋數字／英文＋數字＋符號／自訂」——也就是客人可能根本沒有的代碼——而且沒設退路時，那顆按鈕改成帶語氣的提示：

> ⚠ 這種編號客人可能手上沒有，沒有退路的話會被一直重問。`＋ 加一條退路`

判斷邏輯用現成的 `findStuckCollects()`（`shared/types/ai-script.ts`），跟小幫手異常中心同一支函式，不會有兩套標準。

## 二、整頁審查（依「資料正確 → 看得懂 → 對齊」優先序）

### P0：狀態列會說謊

`flowIssue` 只跑 `validateScriptDoc`，而那支只驗「接線合不合法」。**今天早上那條把客人鎖死的「查詢訂單」，在這條狀態列上顯示的是「流程完整，隨時可以儲存 ✓」。**

這是全頁最嚴重的問題：唯一的綠燈保證了一件它沒有檢查的事。

**修法**：同一條狀態列疊上兩個實際檢查，綠燈才有意義。

| 檢查 | 現成函式 | 文案 |
|---|---|---|
| 接線合法 | `validateScriptDoc` | 還差一步：… |
| 有沒有走不完的題 | `findStuckCollects` | ⚠ 客人答不出「訂單編號」就出不去，建議加一條退路 |
| 觸發得到嗎 | `findUnreachableScripts` | ⚠ 觸發詞會先被自動回覆規則「X」接走 |

分兩級：**擋存檔的錯**（紅、接線壞）vs **不擋但要講的風險**（黃、走不完／輪不到）。

### P0：完成率被當成小灰字

「基本設定」右邊那行 `啟動 6 次・完成 2 次（完成率 33%）`——**完成率 33% 是這一頁最重要的一個數字**，現在跟區塊標題並排、灰色、11px，沒有任何解讀。

**修法**：拉成獨立一列，低於 60% 時變警示色並補一句白話：「有 4 個客人走進來沒走完，多半是卡在某一題」，並且可以點進去（連到那條腳本的對話）。這正是老闆「圖要能直接讀數」那條標準。

### P1：三張卡的順序反了

編輯區由上往下是 **試跑 → 基本設定 → 流程步驟**。新建一條腳本時，第一眼看到的是一個沒有東西可以試跑的模擬器。

**修法**：改成 **基本設定 → 流程步驟 → 試跑**；或把試跑做成右側常駐/底部吸附面板，邊改邊試才是它真正的用法。

### P1：流程圖會捲走

流程圖是這頁最有價值的元件（一眼看懂走向、可點跳），但它塞在「流程步驟」卡的最上面，往下編輯第 5 個節點時它早就捲出畫面，等於在需要它的時候看不到。

**修法**：`position: sticky` 吸在編輯區頂端，或移到右側欄常駐。另外流程圖上應該把有問題的步驟標出來（紅/黃點），跟狀態列同一套訊號。

### P1：欄位名稱要老闆自己發明代號

```
欄位名稱（給答案取個代號，後面判斷、存名單、回覆帶入時都靠它）
placeholder: order_id
```

要一個開店的人想出 snake_case 識別字，是整頁最像工程師介面的一格。

**修法**：改成常用欄位選單（訂單編號／姓名／電話／Email／地址／其他），選了同時把問句範例和欄位代號都填好；選「其他」才手打。代號本身可以直接從問句自動生成，不必讓人看到。

### P1：沒有「複製這條腳本」

「更改地址」和「新增備註」兩條，除了最後一題以外八個步驟完全一樣。現在只能整條重刻。（這次是我用腳本改的，老闆自己在後台做要重來兩遍。）

**修法**：列表項目右鍵或編輯區標題列加「複製一份」。

### P2：同一列混用兩種控制項尺寸（像素級）

`.scripts-branch-case` 這個列（**退路、分支、快速回覆、寫名單四種都用它**）裡：

```html
<el-input ... />                      <!-- 預設尺寸 = 32px 高 -->
<el-select ... size="small" ... />    <!-- small = 24px 高 -->
```

專案沒有設全域 `el-config-provider` 尺寸，所以這是實打實的 8px 高度差，同一列上下不齊。截圖裡那種「右邊那格看起來比較輕」就是這個。

**修法**：整列統一 `size="default"`（或全 small，二選一），四種列一起改。

### P2：同一列的欄寬是隨手給的

```scss
.scripts-branch-field { flex: 1 1 130px; }
.scripts-branch-next  { flex: 1 1 150px; }
```

結果按鈕文字框和「前往…」下拉寬度不一樣，也跟上面那些滿版輸入框的右緣對不齊——截圖裡看得很清楚。而且 `flex-wrap: wrap` 在窄畫面會讓「→」單獨掉一行，變成一支沒有前後文的箭頭。

**修法**：固定成 grid（`按鈕 | 輸入 | → | 下拉 | ✕`），欄寬用 `grid-template-columns`，右緣對齊上方欄位；換行時整組一起換，不讓箭頭落單。

### P2：「✕」出現才佔位，行寬會跳

`v-if="node.skipLabel || node.skipNext"`——一開始打字，整列寬度就縮一次。改成永遠佔位（沒內容時 `visibility: hidden`）。

### P2：兩個節點名稱建議白話化

| 現在 | 建議 | 理由 |
|---|---|---|
| 寫名單 | **存進客人資料** | 「名單」是行銷術語；卡片說明本來就寫「把答案長期存進客人資料」，標籤跟說明不一致 |
| 分支 | **依答案分路** | 「分支」是我們自己發明的，卡片說明已經是對的講法 |
| 快速回覆 | 不動 | LINE 官方術語，屬於「外部必抄」那類 |

⚠️ 這兩個名字散在流程圖、節點卡、下拉選項、積木選單四處，要改就四處一起改（`nodeTypeLabel` / `nodePalette` / `nodeOptionLabel` 同步）。

### P2：優先度滑桿太搶戲

「觸發優先度（60）」給了一支 1–100 的滑桿，說明卻寫「通常不用動」。收進「進階」摺疊區，需要時才展開。

## 三、自動回覆 vs 客服腳本：重疊到什麼程度

### 事實：功能重疊約六成，但執行順位是隱形的

| | 自動回覆 | 客服腳本 |
|---|---|---|
| 怎麼比對 | 含任一／含全部／完全相同／任何內容 | 關鍵字（子字串）、看意思（AI 判斷） |
| 回一句話 | ✅ | ✅ |
| 貼標 | ✅ | ✅ |
| 開網址 | ✅ | ❌ |
| 觸發機器人模組 | ✅ | ❌ |
| 冷卻時間 | ✅ | ❌ |
| 多步驟問答／記住答案 | ❌ | ✅ |
| 按鈕分路 | ❌ | ✅ |
| 存進客人資料 | ❌ | ✅ |
| 轉真人 | ❌ | ✅ |

**「關鍵字 → 回一句話（＋貼標）」這一格是完全重疊的**——腳本用「觸發 → 回覆」兩個節點就做得到，而且還多送轉真人。

真正的問題不是重疊本身，是這三件：

1. **執行順位是隱形的。** 實際順序是：敏感情境 → 進行中的腳本 → **自動回覆** → 啟動新腳本 → AI。也就是**自動回覆永遠排在腳本前面**。兩邊撞到同一個關鍵字，腳本無聲失效，介面上沒有任何提示。（8/7 那次複讀災情、以及昨天做的 `scriptUnreachable` 檢查，處理的都是這件事。）目前只有 anyText 那一種有警告。
2. **兩個入口分在側欄兩個不同群組。** 「自動回覆」在主功能群（第 5 個），「客服腳本」在 AI 群（第 2 個）。使用者沒有任何線索知道同一件事該用哪一邊。
3. **名字沒有區分度。** 「自動回覆」和「客服腳本」都是「客人講話 → 系統自動回」，字面上分不出差別。

### 建議：分三階段，先做 A

**A. 現在做（文案 + 護欄，不動資料結構）**

- 兩頁互相點名。自動回覆頁頂：「只回一句話就結束 → 用這裡；要問客人資料、給按鈕分路、最後轉真人 → 去客服腳本」。腳本頁反向寫一句。
- **自動回覆存檔時檢查關鍵字會不會蓋掉腳本**，跳非阻擋提示：「這個關鍵字會蓋掉客服腳本『查詢訂單』——自動回覆排在腳本前面，那條流程會收不到訊息」。判斷用現成的 `findUnreachableScripts()` 反向查，零新邏輯。
- 側欄把「客服腳本」移到「自動回覆」正下方（同一群組相鄰），讓兩者的關係用位置講出來。

**B. 下一輪（合併入口，不合併資料）**

- 收成一頁「自動回應」，兩個分頁：**一句話回覆** / **多步驟流程**。共用列表、搜尋、啟用狀態。資料模型與執行順位完全不動，純 IA 調整。
- 好處：使用者只要記一個地方，選哪一種在頁內比較就好。

**C. 方向（真正收斂，別急著做）**

- 自動回覆變成腳本的一種「單步驟樣板」：新增腳本 → 選「只回一句話」→ 直接得到 觸發 → 回覆 兩個節點。舊 `autoReplies` 唯讀保留到遷移完。
- 這才真的消滅順位陷阱（全部走同一條排序）。
- **前提**：腳本要先補上自動回覆獨有的三件事——**開模組節點**、**開網址節點**、**冷卻時間**。沒補完就合併會掉功能。

**我的建議**：A 這一輪就做（半天內），B 排下一輪，C 標成方向、等 A/B 的實際使用狀況再決定。

## 六、第二輪：合併成一頁兩分頁（三-B，2026-08-09 完成，當時未 commit、未部署）

### 做法：兩個路由、一組分頁列——**不是**真的合成一支頁面

原本規劃是「收成一頁」，實作時改成保留 `/auto-reply` 與 `/ai-scripts` 兩條路由、共用一組分頁列。理由：

- 異常中心（`useWorkspaceAlerts` ×3）、就緒度引擎（`useSetupStatus`）、教學導覽（`tutorial-topics` ×2）合計 **6 個深連結**指著這兩條路徑。
- 兩頁的權限中介層不同：腳本走 `ai-feature`／`ai.read`，自動回覆只要登入。真的併成一支，非 AI 情境會連自動回覆一起被擋。

換句話說使用者看到的是一頁兩分頁，底下仍是兩個各自完好的路由。

| 落點 | 內容 |
|---|---|
| `useAutoResponseTabs.ts`（新） | 兩個分頁的標籤／路由／一句話說明的**單一來源**；`ai.read` 不足時自動隱藏腳本分頁 |
| `admin/SplitTabs.vue`（新） | 分頁列元件。每顆是真的 `NuxtLink` → 各頁 `useUnsavedChanges` 的 `onBeforeRouteLeave` 照常攔未存變更 |
| `AdminSplitLayout` | 新增 `sidebarHeaderClass` prop |
| `_split-layout.scss` | `.split-sidebar-header--stacked`／`.split-sidebar-tabs`／`.split-sidebar-tab`／`.split-sidebar-blurb` |
| 側欄 | 「自動回覆」＋「客服腳本」兩個入口 → 收成一個「**自動回應**」；`alsoActiveOn` 讓停在腳本頁時該項也亮 |
| 導覽／就緒度 | `nav-ai-scripts` 已不存在 → `useSetupStatus` 的 navTarget 改指 `nav-auto-response`；auto-reply 教學第一步改講「兩種自動回應，先選一種」 |

分頁標籤刻意用「**一句話回覆**／**多步驟流程**」（做什麼）而不是「自動回覆／客服腳本」（叫什麼）——原本的問題就是這兩個名字沒有區分度。物件本身仍叫規則／腳本。

### 靜態版面實測（headless Chrome + 專案編譯 CSS + 真 Element Plus 色票）抓到兩個真 bug

1. **`@media (max-width: 860px)` 是錯的訊號**。會擠到的是**編輯區**寬度（受側欄寬度、使用者拖曳的分隔線影響），不是視窗寬度：1000px 視窗＋寬側欄 → 編輯區只剩 560px 卻不換行。改用 `@container scriptnode (max-width: 620px)`（`.scripts-node-card` 設 `container-type: inline-size`）。已確認 `@container` 通過 Nuxt 的 CSS 打包。
2. **同一張分路卡裡欄數會變**。`比較值` 用 `v-if`，「有填寫」那列少一欄 → 同卡片內各列的「→／前往／✕」左右錯開。改成永遠保留該格（空的 `span`），橫排時撐欄位對齊、直排時 `:empty` 收掉。
3. 附帶：換行後「→」會變成孤零零一行 → 加 `.scripts-branch-arrow` 並在 container query 內隱藏（垂直排列本身已隱含順序）。

**驗證**：`nuxt typecheck` 0 錯、`vitest` 1081 全綠、SCSS 全編過、`nuxt build` 成功、五組版面情境（側欄 240/200px、混合條件對齊、560px 換行、退路鈕兩態、三種燈號）截圖確認。**仍未在真實登入的後台走過一遍**。

## 七、程式碼審查後的修正（2026-08-09）

14 條發現裡 9 條屬實，其中 7 條上線前修掉。

| # | 問題 | 修法 |
|---|---|---|
| 1 | **綠燈又在說謊**：自動回覆規則是背景載入且失敗被吞掉，還沒到手就顯示「不會被自動回覆規則蓋掉 ✓」——正是這次要消滅的那種假綠燈 | 加 `reachabilityState`（loading／ready／failed）。只有 ready 才敢講那句話；failed 直接列成黃色提醒 |
| 2 | **自動回覆的防蓋台會自己安靜關掉**：腳本清單抓失敗 → 回空陣列 → 和「沒有腳本受影響」完全同形 | 加 `scriptListState`；存檔前若非 ready 先補抓一次，仍失敗就跳「沒檢查成功，還是要存嗎？」；畫面上也用 `el-alert` 明說沒檢查到 |
| 3 | **改代號只換到回覆文字**：引擎其實對回覆文字／收集問句／快速回覆問句／重問話術四處都跑 `renderScriptTemplate`，客人會實際收到「請確認 {{order_id}} 是否正確」 | `renameCollectField` 四處一起換；另加「舊名字還被別的收集步驟用著就不動」的保護 |
| 4 | **手打代號打到一半輸入框消失**：`presetKeyOf` 從 `fieldName` 即時推導，打到 `name` 的瞬間翻成內建欄位、`v-if` 移除輸入框、`@change` 永遠不觸發 → 引用沒修好，存檔被擋又看不出原因 | 改用 `fieldMode`（步驟 id → 模式）鎖住，載入時推一次，之後只跟使用者的選擇走 |
| 5 | **兩個步驟可以共用同一個代號**，答案互相覆蓋（驗證器只做「有沒有這個欄位」的比對，發現不了重複） | 選常用欄位時自動讓開（`name` → `name_2`）並說明；既有的重複改用黃色提醒（**刻意不擋存檔**——擋了既有腳本會存不回去） |
| 6 | 試跑面板按「重來」會把剛展開的退路欄位、進階設定一起收掉 | 展開狀態的重置從 `simReset()` 抽成 `resetEditorDisclosure()`，只在換腳本時呼叫 |
| 7 | 「被另一條腳本蓋住」也被加上「（自動回覆與安全層都排在腳本前面）」，把人指去翻錯的地方 | 只有 `autoReplyRule`／`sensitiveTopic` 才加那句 |

另外處理的：`nodeLabelOf` 補回保底值（否則舊資料會顯示「步驟「undefined」…」）；**從範本建立／AI 生成／複製一份**三條路原本都呼叫 `markClean()`，等於宣告一份還沒存的草稿是安全的、切走不攔就整份消失——`useUnsavedChanges` 新增 `markDirty()`，四個草稿入口（含自動回覆的 AI 生成）改用它。
