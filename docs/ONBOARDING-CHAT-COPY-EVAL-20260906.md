## 一、我刻意沒照字面做的（要老闆知道理由）

### 1. 拿掉「接下來大約 3 分鐘就能完成串接」

建議在第二組連線資訊那一步加這句鼓勵。**沒有寫進去。**

- **同一個錯誤四天前才修過**：09-02 拍板把開場的「大約 8 分鐘」拿掉，理由記在
  `useOnboardingChat.ts` 的 `stepWelcomeFresh`：全文 2,100 多字光讀就超過 6 分鐘，
  第一次的人做到 20 分鐘還在拿第二組，那個數字就從「安心」變成「我是不是很笨」。
  結論是**承諾步數不會破功，承諾時間會**。
- **而且 3 分鐘在事實上就是錯的**：從那一刻起還要複製網址、去 LINE 貼上、按存檔、
  開 Use webhook、按檢查、跑到**另一個後台**關自動回應、拿手機加好友傳一句話——七個動作。
- **改成講步數**：「加油，已經快完成了！拿完這組，剩下就是貼一串網址、傳一句話測試。」
  鼓勵的效果留著，可證伪的承諾拿掉。

### 2. 拿掉「可以在 LINE 上自動接收、**回覆**訊息的 MiniMe」

建議的收尾句。**「自動回覆」那半拿掉了。**

- 開通結束的那一刻：**AI 是關的、知識庫是空的**（09-19 拍板「開 AI 整段移出開通引導」，
  理由是剛開通知識庫空的，那時開 AI 客人問什麼都答不出來，第一印象變成「這 AI 很笨」），
  而且流程的最後一步正是叫他把 LINE 內建自動回應**關掉**。
- 所以那一刻**沒有任何東西會自動回覆**。他傳完測試訊息就會發現——而那正好是整段
  流程最想給他成就感的一刻。
- **改成**：「完成後，客人傳到 LINE 的每一句話都會進到後台，你可以直接在那裡回他 🎉」

### 3. 「你現在應該還在 Messaging API 頁面」→ 改成 Basic settings

建議第 11 條要求 Webhook 那段別再叫人重開 LINE Developers（**這點照做了**），
但順帶寫的「你現在應該還在 Messaging API 頁面」**與流程不符**。

- 他的上一個動作是去 **Basic settings** 分頁複製 Channel Secret（`stepSecret` → `walkSecretNodes`），
  所以人停在那裡，不在 Messaging API。
- **改成**：「回到剛剛那個 LINE Developers 分頁——不用重新登入，你現在應該還停在
  **Basic settings** 這一頁。」下一步再叫他切回 Messaging API。

### 4. Webhook 動畫的第①格保留「確認你在哪張卡」

建議第 11 條的精神是「不要讓他覺得要重來一次」。第①格原本是「**選**掛 Messaging API
小字的那張卡」，**沒有刪掉，改成「確認你在**掛 Messaging API 小字的那張卡」。

- **刪不掉**：動畫上的紅色編號①②③④跟文案是**同一套號碼**，而且有測試守著
  （`shared/onboarding-shot-steps.test.ts`）。刪掉①會讓畫面上的②③④跟文案錯開一格。
- **而且同名雙卡是全流程最大的雷**（`line-console-which-card.png` 那張警告圖就是為它做的），
  教學開頭確認一次的成本很低。
- 「重來一次」的感覺改用**前一句**解掉（見第 3 條），不是靠刪步驟。

### 5. 登入講法維持模糊

建議第 5 條要改成「打開 LINE Developers，選『使用 LINE 帳號登入』」。**已依老闆
2026-09-06 拍板「用模糊描述好，因為確實有不同的方式」改回原文**：
「打開 LINE Developers 並登入——用你平常的方式登入就可以（第一次通常選「LINE帳號」）。」

- 原本刻意模糊的理由（08-19，記在 `walkTokenNodes` 的註解）：不是每個人都用 LINE 帳號，
  公司也可能用電子郵件的商用帳號；圈哪一顆按鈕都會誤導另一半的人。
  同一個理由 08-19 也讓 `src-login.jpg` 拍板不配圖。
- 我一度折衷（主線照建議、把商用帳號收進收合區），拍板後把那句補充也一併移除——
  主線既然講模糊，補充就多餘了。

### 6. 後台側欄的「目前官方帳號」維持原樣

建議的通則是「不要用『官方帳號』稱呼 MiniMe」。**對話裡已經全部清掉**，但後台側欄、
切換帳號選單、超管頁（`app/layouts/default.vue`、`super-admin.vue`）都還是用「官方帳號」
指我們自己的帳號。**老闆拍板「後台維持」**，所以這是一個**刻意留下的落差**。

- 示意頁左邊那行也刻意沒改，落差看得見。
- 說得過去的地方：一個 workspace 就是對應一個 LINE 官方帳號（per-OA 計價），
  在後台語境裡不算講錯；真正會混淆的是**取名字那一刻**（那時還沒接 LINE），
  而那一句已經改成「先幫你的 MiniMe 取個名字」。

### 7. Use webhook 不併進貼網址同一支影片

建議第 12 條要求「Use webhook 可以跟上一個步驟一起做、一起呈現」。**老闆採納了我的
建議：維持拆兩步。**

- 08-28 原本拆兩步的理由：貼了沒按存檔是接不通的**第一名**、Use webhook 沒開是**第二名**，
  擠在同一步等於把最容易出錯的兩件事一次唸完。
- 09-06 查證後理由更硬：**完全沒設定過的頻道，畫面上根本沒有 Use webhook 那一列**
  （證據＝`docs/onboarding-shots-src/src-webhook-empty.jpg`），要等網址存好才長出來，
  而且長出來時**預設是關的**（LINE 官方教學的順序也是 Edit → Update → Verify → 開 Use webhook）。
  併成一支＝影片裡會出現他當下畫面上不存在的東西。
- 拆兩步反而是照著畫面真實的變化在走。

## 三、建議自己前後不一致，我選了一邊

### 8. 「通行證」：兩個比喻都不留

較早的口述原話說「你可以先把它們想成是機器人的**通行證**」，但整理過的建議在
「整體用字統一」裡明講**避免使用「通行證」**。**照整理版做，兩個比喻都不用。**

- 理由跟拿掉「鑰匙」一樣：比喻要先被理解才有用，而新手看到「什麼鑰匙／什麼通行證」
  反而多一層要猜的東西。「連線資訊」直白但不需要翻譯。

### 9. 開場的「客服機器人」還留著

建議第 1 條老闆給的開場句是「我會一步一步陪你把**客服機器人**接上 LINE」，
但同一份建議的通則說「我們自己的機器人一律叫 MiniMe」。**目前照他的句子原文保留
「客服機器人」**，只把收尾那半改成「跟你的 MiniMe 成功對話了」。

- 保留的理由：那是**第一句話**，此時使用者還沒建立帳號、還沒聽過 MiniMe 是什麼；
  「客服機器人」是他唯一馬上懂的詞，MiniMe 在下一句取名字時才第一次登場。
- **2026-09-06 老闆拍板「不用改」，本條結案**：開場第一句維持「客服機器人」。
  （要全改的話那句會變成「陪你把你的 MiniMe 接上 LINE」——第一句就出現一個他還不認識的名字。）

## 五、建議有提、但這輪沒做

### 12. 第 3 條的「短影片或三格漫畫」——**2026-09-06 拍板不做，改補在真正會卡住的地方**

建議要求建好帳號後用短影片或三格漫畫呈現「現在要離開 MiniMe，前往 LINE 設定」。
**只做文字過場**，三個理由：

1. **那一步沒有任何按鈕要按**。圖的工作是教他「按哪裡」，而「我們要換場地了」是一句說明。
   老闆原本的抱怨（為什麼突然跳出 LINE 官方帳號）文字過場已經解掉。
2. **下一則本來就有圖**（`oam-account-list.png`）。連兩張圖會把一句「換場地了」講成一段教學。
3. ⛔ **三格裡必有一格是我們自己的畫面**，而 08-28 拍板是「**站內不配圖、站外才配圖**」
   （站內用聚光燈導覽，指得到真實元素）。短影片也被 `public/onboarding/README.md` 明文擋著：
   動畫是整頁截圖裁不同捲動位置拼出來的，**不要改成錄螢幕**（錄的沒人會重錄，過期只能整段作廢）。

**但同一段路上真的有一個斷崖，只是不在他指的位置**——在**「還沒」有官方帳號**那條分支。
原本是「一句話＋一個連結＋零張圖」就把人丟出去，而那句話裡塞了**跨兩個地方的兩件事**
（申請帳號／啟用 Messaging API）。更糟的是「按啟用」那張圖原本**只掛在主線的岔路
「清單裡沒看到我的帳號？」**——也就是他**已經漏做、卡住了才看得到**；而「還沒」這條路
是 100% 需要做這件事的人走的，卻一張圖都沒有。**順序是反的。**
