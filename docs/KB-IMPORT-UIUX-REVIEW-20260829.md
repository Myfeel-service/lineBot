> 老闆看完 D-40 的引導改版後要求：「再次評估現在知識庫匯入的方式跟介面以及 UIUX 的任何介面，給我報告」。

## 一句話結論

**方式是對的，細節也多半用心**（單一投放區自動判別、預覽確認不直接上線、可關窗續跑、失敗白話化、
等待契約——這些在同類產品裡是前段班）。真正的問題集中在三類，按嚴重度排：
**①會說謊的數字（9 條，最傷信任）②半路斷掉的回饋（死路與靜默 15 條）③同一件事多種說法
（條／張／卡／片、資料／知識、半形／全形兩套標點）**。沒有需要重做的架構，全部是可逐條修的工。

## 一、資料正確（最優先）——會說謊的數字

### 🔴 P0

1. **失敗重試「成功」是畫面自己編的**（`KnowledgeImportDialog.vue:1893-1906`，已親驗）。
   結果頁按「重試」後前端**不看回應內容**，一律 `可用 +1、失敗 −1`；而 `/reindex` 走
   `runIndexOnChunk`，再次失敗時是**回 HTTP 200 ＋ `{status:'failed'}`**（`ai-knowledge-chunks.ts:456`
   的 catch 是 return 不是 throw）。「全部重試」還會跳「N 條都學會了」。情境：AI 服務忙碌時
   按重試，畫面說 3 條都學會了，實際 3 條還是失敗——客人問到照樣答不出來，而老闆以為修好了。
   對照：資料頁的同功能（`index.vue:3346-3358`）會重讀真狀態——同一件事兩種誠實度。
2. **「直接匯入 N 條」勾了總表時實際會建 N＋1**（`:470` 的 N＝`includedCount` 不含總表卡；
   `runImport` 把 `overviewPayload` 另行送出；結果頁「總計」又把總表算進去）。
   按鈕說 20、結果頁說 21，兩個畫面對不上，使用者只能自己猜多出來的是什麼。
   邊角：勾選但標題被清空的條目仍計入按鈕的 N、卻不會送出（`:1941-1943` 多濾了空值）。
3. **刪掉的失敗來源，紅字永遠消不掉**（`health.get.ts:53-56`，已親驗）。體檢的來源層查詢
   **沒有濾軟刪除**（知識層有）。刪一份同步失敗的資料 → 待辦「有 1 份資料抓不到內容」還在 →
   點進去撞「找不到這份資料（可能剛被刪除），請重新整理」→ 重新整理也沒用＝永久紅字死路。

### 🟠 P1

4. **「已經有 N 條知識」低估**（`index.vue:1437`）：N 只加總資料清單，**漏算未歸檔的舊版知識**
   （orphan 卡 AI 檢索得到，已驗 `ai-knowledge-chunks.ts:501-503, 578-582` 均無 sourceId 過濾），
   且資料清單有 100 份上限無截斷旗標。`ai-settings.vue:1108` 的同名數字同病。
5. **整站匯入的結論列會低報且可能整條消失**：「共 N 條知識」用的是**索引成功數**（`:1049-1057`
   的 `p.cards`＝`bulk.indexed`），索引失敗的卡**已經建進庫**卻不在 N 裡也沒有清單可重試
   （這條路又刻意不逐條預覽）；**中途關窗**時 worker 收尾直接 `resetAll()`，結論列永遠不出現，
   建了幾份、幾條沒人知道；被中斷卡在「整理中」的頁，伺服器端可能已建好、兩邊都不算。
6. **側欄「N 條」的語意與漂移**：`chunkCount` 是存在資料上的快取值，**含停用／失敗卡**
   （「N 條」≠「AI 用得到 N 條」；刪除確認框「底下 N 條會一併刪除」同一個 N）。
   三條會漂的路：gsheet 同步先算數再重生總表卡（±1，`gsheet-sync.ts:227→241`）；
   `migrate-orphans` 沒濾回收桶、會把已刪的孤兒卡復活成「1 條」但點進去是空的
   （`migrate-orphans.post.ts:24-28`）；匯入補正失敗被 `.catch(() => {})` 吞掉（`bulk-create.post.ts:191-193`）。
   同一畫面「條數 N」與底下卡片列表（即時查、濾回收桶）本來就可能不一致。
7. **修好一張卡，待辦數字不動**（`index.vue:3346-3365`）：編輯彈窗裡按「重新學習」成功後
   只重載該份資料，不刷新體檢 → 「有 N 條內容 AI 沒學起來」停在舊數字＝修好了畫面還紅。
8. **偵測失效與守門擋下時，「最後同步」照走**：`detectStalled` 的來源每輪照寫 `lastFetchedAt`
   （`cron-maintenance.ts:265`）；gsheet 大量刪除被守門擋下時**同時**寫 `failed` 與
   `lastFetchedAt`（`:110-119`）→ 畫面同時顯示「剛剛同步過」＋「抓不到內容」，實情是「抓到了但拒收」。

### 🟡 P2

9. **「其中 M 條含金額或數字」的 M 是「含任何阿拉伯數字」**（`hasNumber=/\d/`，`:1364`）：
   「2 入」「第 3 代」全算，M 恆為上界；而**總表卡（最像價格表的那張）反而不在名單裡**。
   建議收件匣另有兩處：待處理主題 50 筆封頂無旗標（`suggestions/index.get.ts:43`）；
   「都答得出來」講的是**上次掃描當時**，兩次掃描之間可能已不是真的（掃描新鮮度那行有補，尚可）。

## 二、第一次看就懂

- ✅ 摘要先行、主動作先行、步驟指示（D-40 當日已補）、空狀態概念圖——這維度整體是好的。
- **掃描 PDF 30 頁上限事前不講**：第一步只講 10MB，掃描檔超過 30 頁要按下去才撞牆
  （`preview-jobs.post.ts:120`）。一句話成本＝零。
- **兩個「上限」沒有並排講**：探索最多列 100 頁、一次最多匯 50 頁——畫面各講各的，
  第一次遇到的人會以為互相矛盾。
- **基本資訊四格唯讀（類型/狀態/條數/最後同步）長得像沒填完的表單**（`index.vue:438-443`＋
  scss:197-213 的灰底格）：房規明列顯示型資料改用 `.ls-kv` 鍵值格線。

## 三、反術語白話——同一件事多種說法

- **量詞四種並存**：條（條數、N 條知識）／張（N 張卡不會跟著表格更新、共 N 張先列前 M 張）／
  卡・卡片（點卡片上的鎖頭、兩張卡講同一件事）／**錯字「這一條片嗎」**（`index.vue:3475`，已親驗）。
  08-04 拍板全域改名「卡片→一條知識」的殘餘不一致。
- **「資料」vs「知識」同列打架**：側欄標題「你的資料」旁邊主按鈕「加入知識」；空狀態
  「還沒有任何資料」＋按鈕「加入知識」＋工作台「加入第一份資料」＝三種說法。
- **同一型態兩個名字**：手打資料的頁首 caption 顯示「文字」、基本資訊的「類型」顯示「手打」
  （`typeEmoji` vs `typeLabel`，`index.vue:3526-3531`）。
- **150 上限三種單位**：前端「條」、後端「張卡」、表格健檢「列」。
- **半形／全形兩套標點**：模板文案全形「，。（）」；toast／確認框／HEALTH_META 半形「,;()」
  （`:2884, 2346-2353` 等），同一頁兩種排版氣質。
- 個別詞：「AI 換了一種分法」（diff 警示，`:862`）、「證據明確」（產品名合併）偏術語，
  但整體乾淨——chunk／embedding／向量／信心分數等內部詞已確認不在畫面上。

## 四、對齊／整齊（像素級）

- **`.src-todo__muted` 被 flex column 拉成滿版**（scss:759-771，模板 `:303-310`）：同一頁
  另外兩處同型陷阱都打過補丁（`.src-search-empty`、`.chunk-advanced-toggle`），這顆漏了——
  正是房規「column 容器要擋 stretch」的第三處。
- **`:deep()` 寫在全域 partial 裡＝死規則**（`_knowledge-import.scss:603`，已親驗）：
  瀏覽器視為未知偽類整條失效，貼上框的底色沒生效。房規記憶明列 ⛔ 這個坑。
- `.kb-result-summary` 沒有 `flex-wrap`：三格統計窄幅時擠爆。
- `.diff-entry-title` 有 `flex:1`＋ellipsis 但沒 `min-width:0`：長標題會把列撐開。
- **硬編色兩處不走變數**（`#b45309`，scss:144, 533）。
- 側欄三個入口用三種機制湊同一條左緣（width calc／margin×2）；六套膠囊徽章體系並存、
  `badge-yellow` 與 `badge-orange` 值完全相同；死 CSS `.src-alias-badge`。
- `.src-chunk-row { align-items:center }`：「編輯」鈕對四行高的內容垂直置中，浮在中間。

## 七、色彩語意

- ✅ 待辦紅／琥珀分級誠實（紅＝真的影響客人）；「整理好了」綠、「整理中」中性（註解明寫不用紅）。

## 建議修法與優先序（合計約 5 天）

- **P0（1 天）**：①重試改看真回應（比照資料頁做法，兩處統一）②按鈕與結果頁的條數把總表卡
  講清楚（按鈕改「直接匯入 N 條＋1 張總表」或 N 直接含總表；空標題條目即時剔除）
  ③體檢來源層補濾軟刪除 ④錯字「這一條片」。
- **P1（2 天）**：整站結論改用實建數＋失敗清單可重試＋關窗改先確認（對齊「保持開著」文案）；
  「已經有 N 條知識」併入 orphan（或措辭改「至少」）；修卡後刷新體檢；收件匣載入失敗改三態；
  續接逾時要出聲；整理中鎖投放區（或换檔即取消舊 job）。
- **P2（2 天）**：量詞統一「條」＋錯字掃全頁；標點統一全形；四格唯讀改 `.ls-kv`；
  30 頁上限事前講＋兩個上限並排講；`show-word-limit`；五處版面小修（stretch／wrap／min-width／
  硬編色／`:deep()` 改寫）；空 health 彈窗補空狀態與關閉；diff 舊版紅底降為中性。

## 要老闆拍板的三題

1. **「N 條」的語意要挑一種**：A＝維持含停用／失敗但文案改「共 N 條（含停用）」；
   B＝改成只數 AI 用得到的（要動快取邏輯，成本較高）。→ 建議 A。
2. **「資料／知識」與量詞的全域統一**是跨頁改名（08-04 那次的收尾），影響多頁文案，
   要不要這輪一起做？→ 建議做（只動使用者可見文字）。
3. **CSV 支援**（`C-32`⑧ 舊案）：這輪 P1 一起排，還是繼續掛著？購物平台匯出常是 .csv。

## 刻意不列為問題的

- 匯入彈窗不做手機版特化：後台主場景是桌機，vh 三層捲軸在 640px 可用（僅網址被截），
  優先級讓給上面的數字誠實問題。
- 逐條檢查用 v-show 全量渲染：是刻意的（編輯狀態綁索引），150 條上限內效能無虞。
- 預覽輪詢先睡 1.2 秒再打：換來的是取消乾淨，第一秒的「AI 正在讀」文案已補位。
