# 開帳精靈要不要把「接 LINE」整段留到之後——評估報告（2026-09-23）

> 決策紀錄，寫完凍結。狀態一律看 `STATUS.md`（`D-88`）。
> 這份是給老闆的白話報告的工程附錄：多了檔案路徑、查證方法與數字怎麼量出來的。

## 老闆問的

建立帳號時目前會先了解店家輪廓，接著串接 LINE；串接 LINE 的流程很長、很複雜。
能不能建帳時**只先做輪廓**，LINE 留到之後再做，但要在很明顯的地方一直看得到？

## 一句話結論

**建議做，但做法是「拆成兩段」，不是「把 LINE 從開通拿掉」。**

- 第一段「打造」：建立帳號 → 認識你的店 → 當場看到輪廓與五樣草稿 → 自己問它一句。全在我們自己的頁面裡、約 5 分鐘、沒有任何會卡住的地方。
- 第二段「上線」：接 LINE 那四步**照現在的不動**。入口從「逃生門」升格成後台裡到處看得到、而且有信提醒的「上線」按鈕。

前提是三件事要一起改（見「風險」），否則「留到之後」會變成「永遠不回來」。

## 為什麼建議拆（行銷＋PM 的角度）

1. **兩件事的性質不同。** 輪廓是「填我們自己的表」，答案在老闆腦子裡，零失敗點。LINE 是「串接別人家的系統」，要登入兩個別人的後台、拿手機、而且**申請官方帳號的常常不是坐在電腦前這個人**（劇本自己的收合說明就寫著「多半是老闆或前同事用他的 LINE 申請的」）。綁在同一段，第一段的成功率被第二段拖著走。
2. **第一次的「哇」要搬到 LINE 之前。** 現在的魔法時刻＝手機傳一句、後台跳出來，它在 LINE 後面。拆段後第一個「哇」改成「它答對了我的店的問題」（測試對話頁），5 分鐘內、零外部依賴就能到。接 LINE 變成「我想讓客人也看到」的動機驅動，不再是收費站。
3. **成熟 SaaS 都是「先建再接」。** Shopify 先上架商品再接網域與金流；Intercom、Crisp 先設定再裝程式碼；Mailchimp 先做名單與版型再驗網域。原因一樣：接線那一步要在使用者手上**已經有想上線的東西**時才做。
4. **承諾破功發生在最難的一步。** 閘門說「約 7 分鐘」，實況第一次常 20 分鐘。第一段不含 LINE，我們對第一段的承諾（5 分鐘）才守得住；第二段老實講 10–15 分鐘、講清楚要準備什麼。
5. **給對的人做對的事。** 註冊的常是行銷或店長，官方帳號是老闆或代理商的。拆段後，註冊的人能先把「腦」建好，再把接 LINE 交給有權限的人。

## 風險，以及必須一起改的三件事

| 風險 | 為什麼會發生 | 怎麼守 |
|---|---|---|
| **A. 永遠不回來** | 免費帳號建了不接 LINE，就沒有任何 AI 回覆用量，也就沒有營收。今天選「先進後台」的人**沒有任何一封信會去找他** | ①後台四個提醒面保留（已有）②選「之後再接」的人第 1／3／7 天各寄一封信（前置：SES 開通）③第一段結尾一定留一顆清楚的「現在就接」給手上有資料的人 |
| **B. 答五題沒回報** | 揭曉與五樣草稿鎖在 `stepDone`，不接 LINE 就看不到 | 搬到閘門**之前**。網站還在讀就照樣揭曉、講「還在讀」（`revealStoreProfile` 已有這條路，只是上限要從 20 秒調成合理值或改成「先給、讀完再補」） |
| **C. 「拉回精靈」跟「留到之後」打架** | 08-19 拍板每次整頁載入都拉回。如果延後是正當選擇，一個正在匯入知識庫的人按 F5 就被抓回精靈 | 要拍板（`D-88` 第 2 題）。建議：只拉「接到一半離開」的人（貼了任一組連線資訊但沒完成），明確選過「之後再接」的人不拉、靠提醒面與信 |
| **D. 落地頁冷場** | 現在離開精靈落在空的對話列表。08-12 G-11 選對話頁的理由是「他剛傳的那句話就在裡面」——不接 LINE 時前提不成立 | 建議落「測試對話」頁，帶一句「客人會看到的回答，先自己試」 |

## 提案：兩段

**第一段「打造」（約 5 分鐘，全在自己頁面裡）**
建立帳號 → 認識你的店（5 題＋網址，可跳過）→ 揭曉輪廓（猜的標猜的）→ 五樣草稿逐樣採用 → 「試著問它一句」（帶去測試對話頁或內嵌一輪）→ **成績單 A**：輪廓 ✓、採用了 N 樣 ✓、LINE ○ 還沒接。
兩顆鈕：「現在接上 LINE（要能登入 LINE 官方帳號後台，10–15 分鐘）」主要／「之後再接」次要。

**第二段「上線」（現有 LINE 四步，不動）**
入口＝紅帶、側欄點、小幫手卡、三頁空狀態、提醒信。完成後**成績單 B**＝現在那張（接通 ✓、收到第一則 ✓、方案）。

**進度條**：第一段 4 格（建立帳號、認識你的店、看看成果、完成打造）；第二段沿用現在的「取得連線資訊、接收 LINE 訊息、傳訊息測試、完成」。
⛔ 官網示範動畫（`index.vue` 的 `OB_PROGRESS_LABELS`／`OB_BEATS`）抄的是精靈原文，要一起改，不然網站演一套、產品跑另一套。
⛔ 守門測試 `store-profile-onboarding-guards.test.ts` 的「閘門主要動作是接 LINE」「揭曉擺在成績單之前」兩條要跟著改口徑，不是刪掉。

## 順手一定要做：開通步驟紀錄

每個帳號記「到過哪一步、什麼時候、選了哪顆鈕」（一份小文件、只寫不讀畫面）。**沒有它，兩個月後這題還是沒數據**，只能再靠判斷一次。估 0.5 天。

## 四題拍板（建議附在每題）

1. **第一段結尾留不留「現在就接」？** → 建議留、當主要按鈕。手上有資料的人不該被強迫中斷；沒資料的人按次要那顆。
2. **選了「之後再接」還要不要每次整頁載入拉回精靈（08-19 拍板）？** → 建議不拉；改成只拉「接到一半離開」的人。這需要在帳號上記一個一次性的旗標——跟 08-20 拆掉的「每步跳過記憶」不同：那個是每一步各記、會讓人永遠躲掉；這個只記「他看過閘門並且選了之後」，而且**不擋任何提醒面**。
3. **不接 LINE 離開精靈落哪一頁？** → 建議「測試對話」，不落空的對話列表。
4. **提醒信做不做？** → 建議做（1／3／7 天，寄過就記、不重寄），前置 SES 開通。沒有它，「留到之後」對大多數人＝永遠。

## 刻意不做

- 不簡化或拆掉 LINE 那四步裡的任何一步——每一步都是踩過雷才加的（08-12 G-7～G-10、09-02～09-10 各輪）。
- 不重新把「開 AI」放進第一段（08-19 拍板移出；測試對話頁不用開 AI 也能試答，第一段的「哇」不靠它）。
- 不另做第二套「上線檢查」——沿用小幫手就緒度那一份。
- 不改 LINE 為「必要項」的定性：沒接 LINE 就是還沒上線，紅帶照紅。

## 沒有驗證的

- **沒有真實客戶數據**：自助帳號 4 個全是內部測試。「客戶卡在 LINE 的比例」這題目前量不出來。
- 「第一次常 20 分鐘」來自程式註解裡的觀察，不是量測。
- 沒有訪談商家。
- 跟 09-22 `D-85` ①「輪廓放接線之後」的關係：那時的前提是「沒接 LINE 的後台是空殼」。`D-85` P0／P1（`C-217`～`C-222`）做完之後，不接 LINE 也有事可做、有成果可看，**前提變了**，所以這次建議往前多走一步。這不是推翻，是同一個判準（先給得出東西的那一段）在新前提下的結論。
