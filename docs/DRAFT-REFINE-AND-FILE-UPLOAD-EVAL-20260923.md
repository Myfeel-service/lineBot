# 兩題評估：AI 產出能不能「叫它改」、開帳能不能上傳 PDF／Excel（2026-09-23）

> 決策紀錄，寫完凍結。狀態一律看 `STATUS.md`（`D-89`）。
> 老闆 2026-09-23 問：①「如果 AI 產生的結果不滿意，目前只有採用／不採用，是否有跟 AI 溝通修改的機會」②「是否加入可以上傳 PDF 或是 Excel 之類的功能」。

## 兩句話結論

1. **「叫它改」現在完全沒有——而且比沒有更糟：程式裡有一句話承諾「先不要的之後還找得到」，但實際上找不回來。** 另外要先釐清一件事：那五樣草稿**根本不是 AI 生的**，是範本填空。所以這題的真正選項不是「加一顆重生鈕」，而是分三層，由便宜到貴。
2. **上傳 PDF／Excel 早就做好了，而且做得很深**（含掃描檔認字、Excel 一列一張卡）。缺的不是能力，是**位置**：它只活在「知識庫」那一頁，開帳的時候沒有人把它遞出來。

# 第一題：AI 產出不滿意，能不能跟它溝通修改

## 1.1 現況查證（2026-09-23，讀程式）

### 那五樣「草稿」其實不是 AI 生的

`shared/store-profile-drafts.ts` 檔頭鐵律①白紙黑字寫著「**內容用範本生，不用 LLM**……⛔ 不要為了『更聰明』把它換成模型生成」。整個檔案沒有 import 任何模型模組。

| 這一樣 | 怎麼生出來的 | 在哪 |
|---|---|---|
| 加好友歡迎訊息 | 範本字串。店名＋商品前兩樣＋依銷售方式切換一句固定文案 | `store-profile-drafts.ts:94-113` |
| AI 說話的語氣 | 範本字串。產業／商品／客群拼成一句，後面接**寫死的四條安全規則** | `:122-146` |
| 建議標籤 3 顆 | 條件分支。第一顆固定「回購客」，第二、三顆看旺季與銷售方式二選一 | `:160-180` |
| 知識庫初稿 | 只有一句範本文字，讀到 0 頁就整樣不給 | `:258-268` |
| 90 天行銷月曆 | 查表。掃未來 90 天的節日，用節日表自己的切角 | `:192-200` |

**為什麼當初這樣做，理由到今天仍然成立**：要能被測試釘住、每次一樣、不會亂編。這五段話裡有一段會整包覆蓋 AI 的語氣設定（含安全規則），幻覺的代價是客人收到亂講的話。

### 使用者現在只能全收或全不收

- 唯一的互動就是兩顆鈕：`採用` 與 `先不要`（`useOnboardingChat.ts:509-512`）。
- 草稿卡片是**唯讀的**：畫成一塊純文字，沒有輸入框、沒有任何按鈕（`AgentMessageRenderer.vue:224-232`；型別 `agent-messages.ts:131-147` 也沒有可編輯欄位）。
- 整包草稿**全程只算一次**（`useOnboardingChat.ts:485`），就算重跑也是一模一樣的內容（因為是範本），而且重跑會多出重複的標籤與腳本。

### 🔴 有一句承諾是假的

按「先不要」之後，卡片會寫：

> 先不要。之後在「組織與 LINE」頁的輪廓卡還找得到。（`useOnboardingChat.ts:523`）

**但輪廓卡上沒有這種東西。** `AdminStoreProfileCard.vue` 上只有「重新載入」與每一格的「改」「存起來」，**沒有任何地方能把那五樣叫回來**（全檔 grep 過）。更糟的是：那顆「讓 MiniMe 認識你的店 →」只在**還不認識**的時候出現（`:33` 的 `v-else-if="!ready"`），一旦認識了，連重跑精靈的入口都消失。

所以今天按下「先不要」，那一樣就是永久消失。這正是老闆問這題的實感來源。

### 全站其實已經有四種做法，開帳這裡是唯一一個做不到的

| 先例 | 使用者能做什麼 | 在哪 |
|---|---|---|
| **圖文選單 AI 生圖**（最完整） | 有自由文字的風格輸入框（例：「中秋節，深藍配金色，有月亮跟燈籠」）＋每格疊字，**可以無限次重生**，提示字明講「不滿意就再按一次，每次都不一樣」 | `richmenu.vue:115-146`、`:812` |
| **推播文案三版** | **能挑版本**（三版二選一再改）。重生的方式是回月曆再按一次。⛔ 不能下指令微調 | `broadcasts.vue:220-236`、`broadcast-copy-gen.ts` |
| **AI 生客服腳本** | 改描述文字再按一次生成（不限次），草稿直接載進**完整編輯器**逐格可改。另有一層使用者看不到的自動重生（驗證沒過就帶著錯誤重生一次） | `ai-scripts.vue:1884-1915`、`ai-script-generate.ts:206-246` |
| **知識庫匯入預覽** | 每一條都可改標題／內容／標籤／問法、可取消勾選；還有「重新整理並加上清單」**整份重跑**，畫面明講「會算一次用量」，而且失敗時原本那份還在 | `KnowledgeImportDialog.vue:741`、`:2232-2255` |
| **知識缺口建議** | 三個動作：**採用 / 修改後採用 / 忽略**，草稿開在可編輯表單裡 | `KnowledgeSuggestions.vue:57-150` |
| **小幫手用講的改** | **能**。七個操作，而且明文支援「接續上一個提議」——講「改成早上九點」會用同一個操作重新提議 | `ai-admin-agent.ts:606-609`、`admin-ops.ts` |

**結論很清楚：這件事在這個產品裡不是新能力，是開帳這一處落後。**

### 紅線在哪（這題不踩）

2026-08-14 拍板的永久紅線是「對客人說話的東西，最後一顆按鈕永遠留給人」。三級確認流（`ASSISTANT-SEMANTIC-OPS-EVAL-20260813.md` §3.3）裡，🔴 高風險的正確做法就是「AI 建草稿＋講清楚影響＋按鈕留在原本的頁面」。

**開帳這五樣本來就已經是這個做法了。** 只要「改一版」產出的東西**仍然是草稿、採用鈕仍然在**，就不會動到紅線。這一題不需要拍板紅線，只需要決定做到哪一層。

### 已經採用的東西，回得去改嗎（老闆 2026-09-24 追問）

**可以，全部都可以，改的地方就是後台原本那幾頁。** 但有三個實際會踩到的地方。

| 採用的那一樣 | 落在哪 | 能不能改 | 限制 |
|---|---|---|---|
| 加好友歡迎訊息 | 客服腳本，「客人加好友時」永遠釘在清單最上面 | ✅ 內容可改、可停用 | — |
| AI 說話的語氣 | AI 設定的 `systemPrompt` | ✅ 可改 | ⚠️ 見下面第 3 點 |
| 建議標籤 3 顆 | 標籤管理 | ✅ 名字／分類／顏色／說明／狀態都能改 | ⛔ **代號不能改**（`server/api/tag/[id].put.ts:18`「code 不允許修改」）|
| 知識庫初稿 | 知識庫 | ✅ 卡片隨時可改 | 採用當下**什麼都還沒建**，是結束前給一顆按鈕過去整理 |
| 90 天行銷月曆 | 沒有寫入任何東西 | — | 它只是資訊，本來就不用採用 |

**三個坑：**

1. **🔴 精靈沒有給路。** 採用之後那行字寫著「已採用 ✓ 存在『自動回應 › 客人加好友時』」，但它是**純文字、點不下去**（型別 `agent-messages.ts:131-147` 只有 `where` 字串，沒有連結欄位）。而結尾又說了「這些在後台都改得到」——**承諾在、路不在**，跟「先不要之後還找得到」是同一種形狀。
2. **標籤代號建立後不能改。** 名字可以改，代號不行（系統自動生）。不滿意只能刪掉重建。
3. **重跑精靈會蓋掉你手改的語氣。** 語氣草稿是**整包覆蓋** `systemPrompt`，而且沒有任何警告；歡迎訊息有「只准一條啟用中的加好友流程」擋著（會回 409），標籤會多出重複的幾顆，只有語氣是**靜靜被蓋掉**。

**建議**：①把「建了什麼、在哪一頁」做成看得見、點得到的清單（長久歸宿是輪廓卡，當下看得到的是小幫手）②標籤代號不能改這件事，建立時就要講 ③重跑要覆蓋語氣前先問一句，⛔ 不可以靜靜蓋掉。①③已畫進示意頁 v52。

## 1.2 建議：分三層，建議先做第一、二層

| 層 | 做什麼 | 使用者看到什麼 | 成本 | 風險 |
|---|---|---|---|---|
| **① 可以當場改**（建議做） | 草稿卡從唯讀改成可編輯，照「知識缺口建議」那套：**採用／改一下再採用／先不要** | 覺得哪句話不對，直接在框裡改完按採用 | **零模型成本**、零紅線風險 | 幾乎沒有 |
| **② 換一個說法重生**（建議做，只給兩樣） | 歡迎訊息與語氣這兩樣多一顆「**換個說法**」，按了才打模型生一版；⛔ **預設仍然是範本**，沒按就不花錢也不會幻覺 | 「這句太生硬」→ 按一下換一版 → 還是可以改、還是要按採用 | 每按一次一次模型呼叫；可重用現成的 `generateJson` | 生出來的東西要過既有驗證（照推播文案那套硬驗） |
| **③ 用講的溝通**（不建議現在做） | 「語氣再親切一點、不要用感嘆號」這種自由對話 | 真的在跟它講話 | 這是 `C-31` Phase 2 的框架，**5–8 天** | 開帳當下多一個對話介面，反而拉長第一段 |

**為什麼只給兩樣重生**：標籤是三顆條件分支、月曆是查表、知識庫初稿只有一句話——這三樣「重生」沒有意義。真正會讓人不滿意的是**會被客人看到的那兩段話**。

**⛔ 一定要一起修的兩件事**（不修的話做什麼都是補丁）：

1. **那句假承諾**：要嘛把五樣草稿真的放進輪廓卡（可以重新叫出來），要嘛把文案改成實話。建議前者。
2. **輪廓卡的入口**：認識之後那顆按鈕就消失，等於做完一次就再也回不去。輪廓卡要一直有一條「重新整理草稿」的路。

**順手該補的**：五樣草稿的採用與否**目前沒有任何伺服器端紀錄**，只活在前端記憶體。哪幾樣最常被拒絕，是決定「要不要改成模型生」最直接的證據，現在收不到。另外 `/api/tag/create` 完全不寫稽核紀錄（其他寫入端點都有）。

## 1.3 估時

| 事 | 估 |
|---|---|
| ① 草稿卡可編輯（型別＋渲染器＋採用流程） | 1 天 |
| 修假承諾＋輪廓卡放回五樣草稿與入口 | 1 天 |
| ② 「換個說法」兩樣，含硬驗與失敗退回範本 | 1.5 天 |

# 第二題：上傳 PDF／Excel

## 2.1 現況查證（2026-09-23，讀程式）

| 項目 | 實況 | 在哪 |
|---|---|---|
| 支援格式 | **PDF、Excel（.xlsx／.xls）**。⛔ 不收 CSV、Word、純文字檔、PPT、圖片 | `KnowledgeImportDialog.vue:1447`、`upload-url.post.ts:6` |
| 大小上限 | **10MB**，前端擋一次、伺服器擋兩次 | `KnowledgeImportDialog.vue:1461`、`preview-jobs.post.ts:254`、`:111` |
| 怎麼傳 | 直傳 Google 儲存空間（簽名網址，10 分鐘有效），**繞過主機 6MB 的限制**；租戶路徑隔離、讀完即刪 | `upload-url.post.ts:36-58`、`preview-jobs.post.ts:243-260` |
| PDF 掃描檔 | **有認字（OCR）**，30 頁上限、每 5 頁一批；整份認不出字**會明講**，不會默默生出 0 張卡 | `ai-source-extractors.ts:110-126`、`:27`、`ai-preview-jobs.ts:256-262` |
| Excel 怎麼拆 | 兩條路：乾淨表格**一列一張卡、不花模型的錢**；不是表格才整份丟模型切。合併儲存格會展開，第一欄空白的列跳過**並記下來** | `ai-source-extractors.ts:220-273`、`google-sheets.ts:388-444` |
| 一次最多幾張卡 | **150 張**；表格也最多讀 150 列 | `bulk-create.post.ts:32`、`google-sheets.ts:19` |
| 同步還非同步 | 非同步工作＋前端每 1.2 秒輪詢，**輪詢本身就是推進**；8 分鐘沒好就放棄等待（不當失敗） | `preview-jobs.post.ts`、`usePreviewJobPoll.ts:34-35` |
| 檔案重複 | 花錢之前就擋下來，並給兩條路 | `preview-jobs.post.ts:79-85` |
| **店家輪廓吃不吃檔案** | **完全不吃。** 只收網址、打字／選項的答案、從既有資料反推 | `server/api/store-profile/` 三支端點、`AdminStoreProfileCard.vue:72-92` |
| **開帳精靈有沒有上傳** | **沒有。** 對話引擎的互動型別只有四種（選項／打字／密碼／挑東西），**沒有「傳檔案」這一種** | `useOnboardingChat.ts`、`agent-messages.ts:187-205` |
| 開帳結尾怎麼接 | 只把商家官網**網址**帶去知識庫匯入頁，刻意不在對話裡直接寫進知識庫 | `useOnboardingChat.ts:2008-2019` |
| 檔案來源不能重新同步 | 網址與 Google 試算表會自動重抓，**檔案不會**，要重新匯入 | `resync-jobs.post.ts:44-47` |

**所以老闆問的功能，答案是「有，但你在開帳那段看不到它」。** 這跟 `D-85` 查到的那句是同一種形狀：缺的不是管道，是有人在對的時候把它遞出來。

## 2.2 建議：做的是「把既有能力接進開帳」，不是開發上傳功能

| # | 做什麼 | 為什麼 | 估 |
|---|---|---|---|
| ①（建議做） | 「認識你的店」問完網址之後多一句：**「有商品清單或常見問答的檔案嗎？」**，按了就帶去知識庫匯入頁（網址那條已經是這樣接的，照抄） | 開帳當下是商家**手邊最可能有檔案**的一刻，現在完全沒有人問他 | 0.5 天 |
| ②（建議做） | 匯入頁事前講清楚三個上限：**10MB、掃描 PDF 30 頁、一次 150 張卡**，以及**免費方案只有 50 張卡**。現在 30 頁那條要按下去才撞牆 | 商品目錄很容易超過 150 列；免費方案 50 張更容易爆。事後才說＝白等好幾分鐘 | 0.5 天 |
| ③（等拍板，已有編號） | 收 CSV。**這已經是 `D-51` 在等的題**，不是新的 | 購物平台匯出的多半是 `.csv`，現在要商家自己另存成 Excel，而畫面不會告訴他可以這樣繞 | 0.5 天（⚠️ Big5 編碼） |

**⛔ 刻意不建議做的**：

- 把檔案上傳塞進開帳對話裡。要替對話引擎新增一種互動型別，而且他上傳完還是得去審卡片，等於繞遠路。
- 讓「店家輪廓」自己吃檔案。輪廓只有九格，一份 PDF 餵進去九成內容會被丟掉，那些內容的正確去處就是知識庫。

## 2.3 會變成客訴的一件事

**知識卡的張數是計費項目**：免費 50、輕量 399 是 200、入門 799 是 500、成長 1,499 是 1,500（`shared/billing/plans.ts`）。商家開帳當天上傳一份商品目錄，很可能**一次就把免費方案用完**。所以 ① 那一步的文案要先講張數，⛔ 不可以讓他傳完才發現要付錢——那是開帳第一天最傷的體驗。

## 三題拍板（建議附在每題）

1. **AI 草稿要做到哪一層？** → 建議**①＋②**（可編輯＋兩樣可換說法），約 4 天。③「用講的」留給 `C-31` Phase 2，不在開帳做。
2. **那句假承諾怎麼修？** → 建議**把五樣草稿真的放進輪廓卡**並保留入口，而不是把文案改軟。做完一件事看不到任何變化，是最傷信任的那種 bug。
3. **檔案上傳要不要收 CSV？** → 這題等同 `D-51`，建議一起拍。若不收，至少要在畫面上告訴商家「請先另存成 Excel」。

## 沒有驗證的

- 沒有訪談商家。「哪幾樣草稿最常被拒絕」目前**收不到資料**（沒有伺服器端紀錄），所以「該不該改成模型生」是判斷不是數據——這也是為什麼建議順手補上紀錄。
- 「換個說法」的模型成本沒有實測。量級參考：讀官網那次 12,136 token、2.5 秒（`D-85` 實測），重生一段歡迎訊息遠小於此。
- 沒有量過真實商家的商品目錄通常幾列，150 張卡的上限夠不夠是推測。

## 相鄰不重疊

`C-31`／`D-58`（小幫手用講的操作）是第一題第③層的框架，⛔ 不要在開帳另做一套；`D-51`（收不收 CSV）就是第二題的③；`D-85`／`C-221`（五樣草稿）是第一題要改的對象；`D-88`（開帳拆兩段）決定這些東西落在第 1 段的哪裡。
