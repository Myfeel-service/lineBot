# 加好友歡迎訊息：設定方式 UX 評估＋競品對照（LINE 內建／Omnichat）

> 2026-08-22。評估對象＝ C-56（commit `65ba6ee`）上線後的設定動線。
> 本文是決策紀錄，寫完凍結；拍板結果與後續進度一律看 `STATUS.md`（`D-23`）。

## 一、我們現在的樣子（實況，不是設計稿）

商家要設定「客人加好友時說一句話」，路徑是：

1. 側欄「**自動回應**」→ 進到腳本頁。
2. 沒選任何腳本時，中間是範本牆＋AI 生成框 → 點「**加好友歡迎訊息**」範本 → 改文案 → 存檔。
3. 或者自己建腳本，在觸發步驟把「觸發方式」從關鍵字切成「**客人加好友時**」。

能力面：歡迎不只能說一句話——因為底層是腳本引擎，可以**接著問問題、把答案存進客人資料、貼標、送圖文模組、轉真人**；有試跑面板（「模擬客人加好友」按鈕）；一個帳號只能有一條（存檔 409 擋）；編輯器有 alert 提醒「LINE 內建那則要去關掉」。

## 二、LINE 官方帳號內建的做法（查證 2026-08-22）

- **入口是一級選單項**：LINE Official Account Manager 左側「聊天室相關」→「**加入好友的歡迎訊息**」——名字就是使用者心裡想的那五個字。
- **一次最多 5 則**，型態同群發（文字／貼圖／圖片／優惠券／圖文訊息…），單則文字上限 500 字。
- **變數**：好友的顯示名稱、帳號名稱、表情貼。⚠️帶「好友顯示名稱」的訊息**只有同意分享資料的好友收得到**——拒絕分享的人整則收不到（他們自己文件寫的）。
- **沒有**條件式、A/B、預覽模擬器；停用開關在「設定→回應設定」。
- 另有獨立功能「**漸進式訊息**」：加好友後第 N 天自動發（第一天不計入），可按性別／年齡層／OS／地區加條件——drip 跟歡迎是兩個功能。

## 三、Omnichat 的做法（查證 2026-08-22）

- **也是一級功能**：後台「通訊渠道」→「社群常用訊息與設定」→「**歡迎訊息**」→ 選平台。
- LINE 的觸發＝**加入好友後**；內容二選一＝**純文字**（帶聯絡人姓名參數）或**機器人模組**（＝接互動流程，跟我們的「腳本」同一個思路）。
- **打對台問題他們也解不了**：教學叫你自己把 LINE 內建 Greeting messages 設 Disable、回應模式選手動——靠文件，不靠系統偵測（LINE 沒有 API 可以讀/關 OAM 的內建歡迎，誰都偵測不了）。
- **預覽方式＝自己封鎖再解除**重加一次好友——沒有模擬器。

## 四、差距表

| 面向 | LINE 內建 | Omnichat | 我們（C-56） |
|---|---|---|---|
| 找得到嗎 | ◎ 一級選單，名字就叫歡迎訊息 | ◎ 一級選單 | △ 藏在「自動回應」的範本牆／觸發方式第三顆選項 |
| 富內容（圖／貼圖／優惠券） | ◎ 編輯器內直接放，5 則 | ○ 接機器人模組 | ○ 接圖文模組（要先去別頁做好模組） |

## 五、結論

**架構是對的，入口是弱的。**「做在腳本裡」讓我們一次拿到收資料／貼標／轉真人＋試跑＋防呆，這些兩家競品都只有部分；但兩家競品都把「歡迎訊息」做成**一級的、名字就叫歡迎訊息**的設定，我們的入口藏在「自動回應→範本牆」，商家腦中的關鍵字（歡迎訊息）跟我們的名詞（腳本／觸發方式）對不上。這正是 08-09 自動回應合一拍板的哲學可以再用一次的地方：**一種東西、兩種深度——入口獨立、實作共用**。
