### A2-2. ⚠️ 05 表第 3 條紅字:啟用幕後 = 放棄 3D 驗證,爭議款自負

05（幕後功能API）申請書比 07 多一條紅字（07 沒有這條）:

> 「3.全平台預設商店為 3D 交易,如會員申請**啟用信用卡幕後同等於不使用信用卡 3D 驗証機制**,

**白話**:一般刷卡有 3D 驗證（銀行發簡訊給持卡人),持卡人事後主張「不是我刷的」時,責任在銀行。
**幕後扣款沒有 3D**（持卡人不在場,沒人能收簡訊)→ **持卡人主張爭議時,錢由我方吸收。**

**這對訂閱制是不可避免的** —— 全世界的月租訂閱都是這樣（card-not-present recurring)。
但它是真的商業風險,要知道:

| 我方現況 | 效果 |
|---|---|
| **首刷走 UPP 且過 3D** | 第一筆有 3D 保護,只有**續扣**那幾期沒有 |
| 已存 `termsAcceptedAt` / `termsVersion` | **爭議時的舉證資料**（客戶當初明確同意每月扣款) |
| 付款頁 `ProdDesc` 帶品牌名 MiniMe | 客戶對帳單看得懂是什麼,降低「這什麼鬼扣款」型爭議 |
| ⚠️ **收據信尚未開通（SES 未設）** | **這是目前最大的缺口** —— 收得到收據的客戶爭議率明顯較低。上線前應該開 |

→ **結論:不是不能做,是要接受這個風險並把舉證與通知做好。**
   **SES 通知信從「選配」升級成「上線前該做」。**

#### ⚠️ 「去 Amplify 後台查我們的 IP」是行不通的（2026-08-04 查證）

1. **Amplify 的 SSR 是 AWS 託管的 Lambda,對外 IP 來自 AWS 的共用位址池,會變,而且
   Console 裡沒有任何地方顯示「你的對外 IP」。** 不是我們沒找到,是它不存在一個穩定值。
2. **Amplify Hosting 的 SSR compute 不支援接 VPC**（GitHub `aws-amplify/amplify-hosting`
   #3302、#3362 至今仍是待實作的功能請求）→ 業界標準解法「Lambda 接 VPC + NAT Gateway
   取固定出口 IP」**在 Amplify 上直接用不了**。

#### 若 PAYUNi 堅持單一固定 IP,可行方案

**好消息:只有「幕後」那幾支需要固定 IP** —— `/api/credit`（續扣）、`/api/credit_bind/*`
（查詢/解約）。客戶刷卡的 UPP 付款頁是瀏覽器導轉,不受 IP 限制;`trade/query` 目前從
Amplify 打是通的,也沒被擋。所以要處理的只有 2~3 支呼叫。

**業界怎麼解「serverless 打需要 IP 白名單的金流」**（2026-08-04 查證,這是常見到有整類 SaaS 在賣的問題）:

| 方案 | 做法 | 粗估成本（待核實） | 工 | 適用性 |
|---|---|---|---|---|
| **① 請金流放寬成網段** | 多數金流可談;先問 | 0 | 0 | **首選,等窗口回覆** |
| **② 自架小出口代理**（次選） | Lightsail/EC2 最小機 + 固定 IP(Elastic IP),跑一個 HTTPS 轉發代理;程式設 `HTTPS_PROXY` 讓**只有續扣/解約那 2~3 支**走它 | 約 USD 3.5~6/月 | 半天 | ✅ 不需 VPC,Amplify 可用 |
| ③ 靜態 IP 代理 SaaS | QuotaGuard / Fixie 這類「固定 IP 出口即服務」——業界對 Heroku/Vercel/Lambda 這類平台的標準解;設兩個環境變數即接上 | 約 USD 19/月起 | 1 小時 | ✅ 最省事但比自架貴;金流流量走第三方,資安要評估 |
| ④ VPC + NAT Gateway | AWS 官方解 | USD 32/月起+流量 | 中 | ❌ **Amplify SSR 不支援 VPC,用不了** |
| ⑤ fck-nat 便宜 NAT 機 | 社群省錢版 NAT | 約 USD 3/月 | 中 | ❌ 同樣要 VPC,用不了 |

→ **結論:先問①;被拒就做②**（我方程式只要在 `chargeCreditToken`/`cancelCardBinding` 加一個
可選的 proxy 環境變數,約 20 行,可以先寫好備著,切換只是設個 env）。
③ 適合完全不想管機器的情況。**付款頁（UPP）與查單不受 IP 限制,所以出問題半徑很小。**

**先空著,或註記「待確認」。** 填一個當下的 IP 進去,過幾小時就失效、幕後扣款照樣被擋。

### B3. 全額折抵那一期不開發票,會計認不認

**用一個具體例子講**:

| 時間 | 發生什麼 | 發票 |
|---|---|---|
| 7 月 | 客戶付 799 買「入門」方案 | ✅ 我們開了一張 **799** 的發票 |
| 8 月 | 因為某個原因(例如服務中斷賠償),我們決定補他 **400 元**。老闆拍板:**不退現金,改成折抵下期** | — |
| 9 月 | 該扣 399(他降到「輕量」)。有 400 可折 → **399 全部被折光,這個月他不用付錢** | ❓ 要不要開發票? |

**我的做法:9 月不開發票。**

**為什麼**:那 400 元是「7 月那筆 799 裡面的錢」,7 月已經開過發票、也已經報過稅了。
9 月只是把那筆已收的錢拿來抵,**沒有任何新的錢進到公司**。
如果 9 月還為它開一張 399 的發票,等於**同一筆錢開了兩次發票、銷售額被報了兩次**。

**所以要問會計的就是**:「這樣不開,對嗎?」

若會計說不行,替代做法有兩條,但都更麻煩:
1. 開一張 0 元發票(不確定財政部認不認)
2. 改成真的退現金 400 給客戶 + 對 7 月那張發票開折讓(要動退款 API,而且跨月只能走折讓)

### 你要做的四件事（順序照做）

#### ① 驗證寄件網域

AWS Console → **Amazon SES** → Verified identities → Create identity → 選 **Domain** → 填 `myfeel-tw.com`
→ AWS 給你幾筆 **CNAME**（DKIM）→ 加到網域的 DNS → 等它自動驗證通過（通常幾分鐘到數小時）。

> 這一步是在證明「這個網域真的是你的」,否則任何人都能冒用你的網域寄信。

#### ② ⚠️ 建 SSR Compute Role 並給 SES 權限 ← **最容易漏掉的一步**

**Amplify 的 SSR 執行環境預設「沒有」任何 AWS 服務權限。** 只設環境變數的話,
程式跑起來會拿不到憑證 → SES 回 `AccessDenied` → 信永遠寄不出去,而且**因為我方設計成
「寄信失敗不影響主流程」,你只會在 log 看到錯誤,金流一切正常** → 很容易以為已經在寄了。

做法（AWS 於 2025-02 才開放這功能):
1. IAM → 建 Role,**自訂信任政策**:
   ```json
   { "Version": "2012-10-17", "Statement": [{
       "Effect": "Allow",
       "Principal": { "Service": ["amplify.amazonaws.com"] },
       "Action": "sts:AssumeRole" }] }
   ```
2. 附一個只給寄信的最小權限政策:
   ```json
   { "Version": "2012-10-17", "Statement": [{
       "Effect": "Allow",
       "Action": ["ses:SendEmail"],
       "Resource": "*" }] }
   ```
3. Amplify Console → App settings → **IAM roles** → 指派這個 **SSR Compute role**。

#### ③ 申請「出 sandbox」

SES → Account dashboard → **Request production access**。
沙盒模式只准寄給「你自己已驗證過的信箱」,要寄給客戶必須離開沙盒。通常 1 個工作日內核准。

**表單怎麼填（AWS 會問三件事）**:

| 它問什麼 | 照這樣寫 |
|---|---|
| Mail type | **Transactional** |
| Use case description | 只寄交易性通知給已付費客戶:付款收據、自動扣款失敗提醒、續扣前提醒、用量額度通知。**不寄行銷信、不購買名單**,收件人一律是客戶自己在後台填寫的帳務信箱。 |
| 如何處理退信與客訴 | 我方於 SES Console 監控 Bounce / Complaint 比率;客戶信箱由本人於後台自行填寫並可隨時修改;所有信件皆為交易通知,不含訂閱式行銷內容。 |

> ⚠️ 別寫成「行銷/推廣」——那會被要求補一堆退訂機制與名單來源證明。我們確實只寄交易信。

#### ④ 填兩個環境變數（Amplify → Environment variables）

| 變數 | 值 | 說明 |
|---|---|---|
| `EMAIL_FROM` | `MiniMe <noreply@myfeel-tw.com>` | **網域必須是 ① 驗證過的那個**,否則 SES 直接拒寄 |
| `AWS_SES_REGION` | 例 `ap-northeast-1` | SES 是分區域的,**填錯區域會找不到你驗證過的網域** |
| `EMAIL_REPLY_TO`（選填） | `service@myfeel-tw.com` | 客戶按回覆時的收件信箱 |

**帳號密碼不用填** —— 憑證由 ② 的 role 提供。

#### 驗收方式

設完重新部署,然後在後台做一筆測試付款 → 應該收到「付款成功通知」。
沒收到就看 Amplify 的 log:
- `[email] 未設定 SES（EMAIL_FROM / AWS_SES_REGION）` → ④ 沒設好
- `[email] 寄信失敗：… AccessDenied` → **② 的 role 沒建或沒指派**
- `[email] 寄信失敗：… not verified` → ① 沒過,或 `EMAIL_FROM` 網域不符
- `Message rejected: Email address is not verified`（只有收件人被擋）→ ③ 還在沙盒
