# LINE 訊息還剩幾則：放在哪裡、誰來提醒（`D-146` 評估）

2026-10-22。老闆原話：「LINE 這個月還剩幾則 這個應該算是很重要的訊息／評估 UIUX 要怎麼呈現 是否只出現在推播 我認為至少 dashboard 要出現 且 小幫手等提醒功能也評估一下要不要加入」。

示意＝Design 畫布 `7SMSm4qs2eZhwoPLiRvnbd`（11 張畫面＋左上角四題）。這份是附錄：當時查到什麼、為什麼這樣建議。

---

## 一句話結論

**平常安靜地放在兩個地方（登入後第一頁、推播頁），快用完、用完時才主動講，而且要趁 LINE 還送得出去先講。**

比喻：這個數字像車子的油表。油表一直在儀表板上（登入後第一頁那一條），但沒有人會一直盯著它；
真正有用的是**剩一格時亮黃燈**（八成）、**沒油時亮紅燈**（用完）。
麻煩的是，我們用來「打電話通知你沒油」的那支電話（LINE 通知）**本身也吃這缸油**——
所以亮黃燈的時候就要先打，沒油了只能改寄信。

---

## 一、先把這個數字講清楚（畫面上每一句都照這個寫）

**會用掉則數的**（2026-10-22 逐支查過程式）：
- 推播（群發、用了客人名字一人一則送的都算；一位收件人算一則）
- 你在後台回客人的訊息（含客服預存回覆）
- 推播的試發
- 活動頁：客人加好友後送的那一則
- 傳給店家同事的 LINE 通知（客人找真人、早上的摘要、出大事）——**用的是店家自己的官方帳號**

**不算的**：AI 回客人、自動回應回客人（都是「回覆客人剛傳來的那則」，LINE 不計）。

**MYFEEL 10/1～10/21 實際**（向 LINE 唯讀查每天各種送法的則數）：
| 送法 | 則數 | 佔 |
|---|---|---|
| 群發推播（4 天） | 5,500 | 約八成 |
| 一則一則送的（真人回覆、LINE 通知、試發、活動頁、一人一則的推播） | 1,267 | 約兩成，**平均每天約 60 則** |
| AI／自動回應的回覆（不算錢） | 2,215 | — |

LINE 說這個月已送約 6,810 則、上限 306,000 則——**MYFEEL 這個月只用了 2%，這輩子大概碰不到上限**。

兩個要寫在畫面上的事實（照 LINE 官方文件）：
1. **上限＝方案內含＋加購的則數**，LINE 只給合計、不給「方案內含幾則」。MYFEEL 的 306,000 不是「免費的還剩這麼多」。
2. **「已送」是大約數**，而且包含在 LINE 官方帳號後台手動發的。畫面一律寫「約」；「用完了」以 LINE 真的擋下來為準。

**誰真的會碰到上限：小店。** LINE 免費方案每月只有幾百則（各方說法不一，以 LINE 公告為準）。
照 MYFEEL「一則一則送的每天約 60 則」的節奏，**就算一則推播都不發，幾天就用完**；小店量比較少，
但光是早上的摘要傳給 3 位同事，一個月就是 60 多則。所以這件事對 MYFEEL 是資訊、對新進的小店是會出事的。

## 二、建議的三層

### 第 1 層：隨時查得到（安靜）
| 位置 | 做什麼 | 狀態 |
|---|---|---|
| 登入後第一頁（客服對話統計） | 數字列**上面**多一條「LINE 訊息　這個月還剩約 N 則」＋細進度條＋「已送約／上限・11/1 重算」，滑過去講上限含加購、哪些會用到 | 新（示意 ①） |
| 推播頁 | 左邊一行＋發送前不夠送會警告 | 已做（`C-380`） |
| 問小幫手 | 「LINE 還剩幾則？」答得出來，順便講這個月用在哪（群發幾成、一則一則送的幾成） | 新（示意 ④） |

⛔ **為什麼不是數字列的第五張卡**：那一排跟著右上角的日期區間變（近 7／30／90 天），這個數字不會——
放進去會被讀成「近 7 天剩幾則」。單獨一條、寫明「每月 1 號重算」。

### 第 2 層：快用完（用到八成）
- 那一條變黃，多一行講用完會怎樣＋「前往 LINE 官方帳號後台」
- 小幫手「目前狀況」黃色一項（建議處理，不進紅點）
- **LINE 通知傳一則，這個月只傳一次**，傳給勾了「出大事」的同事——跟「AI 用量八成」那則同一套做法與同一個收件分類

### 第 3 層：用完了
- 那一條變紅
- 小幫手紅色一項（現在影響客人、亮紅點）：推播、後台回客人送不出去＝客人收不到，所以算「影響客人」
- **每一頁最上面一條紅、關不掉**——跟「AI 已停止自動回覆」那條同一個元件、同一個份量。
  所有角色都看得到（客服在後台回的訊息也會失敗），「前往 LINE 官方帳號後台」只給管理員。
  登入後第一頁那一條已經是紅的，那一頁不再重複掛（同 AI 橫幅在帳單頁不掛的理由）。
- **寄 Email 給帳號負責人，這個月只寄一次**：用完那一刻 LINE 通知自己也送不出去。
  這正是既有待辦 `C-90`（LINE 通知全滅時改寄 Email）的情境，建議就從這件開始做 `C-90`。

## 三、評估過、不建議放的地方
| 位置 | 為什麼不放 |
|---|---|
| 每一頁頂端常駐一行 | MYFEEL 這個月只用 2%。天天看到一個不會出事的數字，真的快用完時反而不會看（油表盯久了就不看了） |
| 設定 →「組織與 LINE」的「目前方案」卡 | 那張卡是 MiniMe 的方案（AI 回覆則數）。放一起，兩種「則」會被當成同一種 |
| 每日摘要每天報一次 | 每天念一個幾乎不變的數字＝噪音；八成那則已經講過，用完了摘要也送不出去 |
| 客服對話頁輸入框上方再一條 | 用完時每一頁最上面已經有紅條，同一件事不講兩遍 |
| 組織總覽、超管帳號列表 | 對店家沒有新資訊；之後要看「哪些客戶快用完」再另外加 |

## 四、兩種「則」要分清楚
加了 LINE 這個數字之後，現有的 AI 額度橫幅「**本期額度只剩 N 則**」會分不清是哪一種。
建議同一批改成「**AI 回覆**本期只剩 N 則」，LINE 那邊一律叫「**LINE 訊息**」。
（改用語要全站一起改：AI 額度橫幅、小幫手兩顆 AI 額度提醒、AI 用量八成那則 LINE 通知。）

---

## 五、怎麼知道快用完（白話）
- LINE 不會主動告訴我們，要去問；一次問兩個數字，很便宜。
- 已經有一個「每小時對每個帳號檢查一次、有出大事就傳 LINE」的排程（台灣時間 9～21 點）。順路多問一次 LINE：
  過八成→傳那一則 LINE 通知；用完→寄 Email。每個月各一次，用跟 AI 額度同一種「這個月傳過了」的記號。
- 任何一次送東西被 LINE 擋下「這個月用完了」，當場記下來——紅色不用等下一個整點。
- 小幫手、登入後第一頁、每一頁紅條都讀同一份結果（5 分鐘內不重問）。

## 六、順便發現
1. **店家收到的 LINE 通知吃的是店家自己的則數**（用店家的官方帳號送）。對小店是看不見的成本：
   我們越貼心、通知越多，他越快用完。改成由 MiniMe 自己的官方帳號送，成本轉到我們身上、同事要另外加 MiniMe 好友，
   牽涉到「設定 → LINE 通知」整套綁定流程——**另開一份評估**，不在這一批。
2. `C-380` 推播頁滑過去那句「哪些會用到」漏了「活動頁加好友後送的那一則」，評估當下已順手補上（併進 `C-380`）。

---

## 七、要老闆點頭的四題
1. 登入後第一頁放一條「LINE 訊息」：平常灰一行，八成變黃、用完變紅？（建議：要）
2. 快用完、用完時主動講：小幫手黃／紅＋用完時每一頁最上面一條紅？（建議：要）
3. 八成時傳一則 LINE 通知；用完時改寄 Email（＝從這件開始做 `C-90`）？（建議：要）
4. LINE 通知改用 MiniMe 自己的帳號送、不吃店家則數 → 另外評估？（建議：另案）

## 八、工期
1～3 題一起做約 2 天：登入後第一頁那一條＋三種樣子半天；小幫手兩項＋每一頁紅條半天；
每小時檢查＋八成 LINE 通知＋用完寄信（含 `C-90` 的收件人與去重）約 1 天；問小幫手＋兩種「則」改名約半天。
