## 決定

### 先問客人清單（`C-375`）

1. **照順序就是下一題**：「答了 →」只在設了跳題的那一題出現（例：查詢訂單第 1 題「答了 → 直接到最後」）；
   要跳題從那一題的「⋯」→「答了改跳到別題」打開，✕ 改回照順序。
2. **跳題只能往後**：下拉只列後面的題目＋「直接到最後」。換順序後變成往回跳的，那一題標紅「會跳回前面那一題」，⛔ 不偷偷改掉。
3. **拖曳換順序**：每題左邊 ⠿（同機器人模組的訊息卡），「⋯」裡另有上移／下移。規則：
   - 原本接「下一題」的路（最後一題的「直接到最後」也算）→ 換完接新的下一題；
   - 指定跳到哪一題、或不是最後一題卻「直接到最後」的 → 跟著那一題走、不變（查詢訂單第 1 題「答得出編號就收尾」是刻意的）；
   - 開頭接新的第一題。
4. **存進客人資料勾在每一題上**，最後一段不再列一排（存的格式不變，還是最後那一步「存進客人資料」）。
5. **次要動作收進每題的「⋯」**：刪除這一題、答了改跳到別題、客人可能沒有這個資料、上移、下移（全站次要動作本來就收在「⋯」）。
   ⛔ 「這種編號客人手上可能根本沒有、又沒給路」的提醒照樣直接露出——那是客人會被一直重問的事，不能藏。
6. 「客人說沒有」打開時先帶好：按鈕字「我沒有＋這一題的名字」、去向＝下一題（別家預設也是下一題）。
7. 「傳截圖也算回答」改成編號類題目旁邊的小標「截圖也收」（原本長在「答了 →」那一列後面，那一列平常不顯示了）。
8. 常用欄位加「備註」（MYFEEL 那題的代號 note 顯示成「備註」）。

不做：一次只展開一題（證據最少）、「給客人按鈕選」收進題型選單（要動資料結構，這次沒被點名）。

### 客人加好友時（`C-374`）

漸強的做法跟我們最像（加好友是觸發條件之一、一個帳號一條），但它**建好就不能改類型**；我們以前可以在「什麼時候開始」切來切去，
會把「查詢訂單」切成歡迎訊息，或把歡迎訊息切回一般的、左邊那一列變回「還沒設定」。LINE、ManyChat 則是獨立一格。

決定：**只從清單最上面那一列進**（那一列原本就在、導覽也教了），打開後「什麼時候開始」直接寫「客人加好友時」、不給切；
一般的自動回應「什麼時候開始」只留兩種；「新增」的起點拿掉加好友那張卡（一個帳號只有一條，不是「新增一條」）。
