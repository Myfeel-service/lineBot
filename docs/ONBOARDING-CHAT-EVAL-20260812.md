# 開通引導對話流程評估（2026-08-12）

> 🧊 **凍結文件（決策紀錄）。** 記錄評估當下看到什麼、為什麼這樣判斷。
> 待辦與現況一律看 [`docs/STATUS.md`](./STATUS.md)（本次入表 `G-7`〜`G-12`）。

**範圍**：新客戶第一次進來、用聊天方式引導建立資料的整條流程——
`app/pages/admin/onboarding.vue` ＋ `app/composables/useOnboardingChat.ts` ＋
`setup-status` / `first-message` 兩支訊號端點。對照規格 `ONBOARDING-CHAT-DESIGN-20260807.md`。
純程式碼與規格審閱，未實機走 LINE 憑證流程（與 §8 實作紀錄同一限制）。

## 總評

骨架是對的，而且守住了設計釘死的原則：完成判定全部來自後端真實訊號、每步可跳過、
續走靜默跳過已完成項、成績單查不到就不出（不說謊）、Webhook 檢查失敗依真實錯誤分流。
8/7 兩輪審查修掉的 13 項也都還在。

問題集中在**教學內容跟真實世界對不上**：精靈自己的機制很誠實，但它「教使用者去 LINE
那邊做的事」有一處教錯、兩處沒教，而 LINE 端恰好是新手唯一會卡住的地方。

## 發現（依嚴重度）

### 1. 🔴 LIFF 步驟教錯 Endpoint——「先填你的官網就行」（G-7）

`useOnboardingChat.ts` stepLiff 的 help 卡第二條教「Endpoint 先填你的官網就行」。
但系統要求 LINE 登記的 Endpoint 必須是 `{正式網址}/liff/lead`
（`liff-endpoint-check.get.ts` 的 `expectedUrl`；2026-08-07 老闆拍板網址不一致一律紅）。

照精靈的教學做，會發生兩件事：

1. 之後辦活動發綁定連結，客人點開 → LINE 登入完被送回店家官網，活動頁永遠打不開。
   **這正是 2026-08-07「無法完成綁定」災情的成因**（login callback 永遠回 console 登記的
   Endpoint URL，跟連結網域無關）。
2. 設定頁與小幫手的 LIFF 登記檢查立刻亮紅——精靈教一套、健康檢查罵一套，
   剛開通完右下角就掛紅點，新客戶第一印象是「我照著做還是錯」。

**建議修法**：這一步照 Webhook 步驟的手法，直接給一張複製卡放正確網址
（跟 `liff-endpoint-check` 同一個來源算 `{base}/liff/lead`，別另抄一份口徑），
教學文字改成「Endpoint 貼下面這串」。

### 2. 🟠 沒教「啟用 Messaging API」——剛申請 OA 的人拿不到鑰匙（G-8）

流程問「有 LINE 官方帳號了嗎？」→ 還沒 → 給申請連結 → 申請完回來，
下一步教學是「打開 LINE Developers → 選你的官方帳號 → Messaging API 分頁」。
但剛申請好的官方帳號**在 LINE Developers 裡看不到**——要先回官方帳號管理後台（OAM）
的「設定 → Messaging API」按啟用，channel 才會生出來。

新手在這裡沒有任何線索：畫面上沒有他的帳號，精靈也沒提這個步驟，只能去 Google。
這是真實開通流程裡最常見的卡點，而且恰好只打中「還沒有帳號」那批最生的新手。

**建議修法**：「還沒」分支多一步，或至少在 Token 的 help 卡加一條
「在 Developers 找不到你的帳號？先回官方帳號後台啟用 Messaging API」。

### 3. 🟠 沒教關 LINE 內建自動回應——之後每句話客人收到兩套回覆（G-9）

LINE 官方帳號預設開著內建的「自動回應訊息」。精靈教開 Use webhook，但沒教關這個，
結果：老闆拿手機測試那一刻，後台等待卡亮起 🎉 的同時，手機收到 LINE 罐頭
「感謝您的訊息…」；之後每個客人講話都會收到兩套回覆（LINE 罐頭＋我們的 AI），
看起來像壞掉。

這個設定 LINE 沒有開放 API，系統偵測不到（小幫手救不了），**只能靠教**。

**建議修法**：Webhook 那步的教學加一句「回官方帳號後台的回應設定，把回應模式切成
聊天機器人、關掉自動回應訊息」。一句話成本，擋掉最常見的「為什麼客人收到兩則」。

### 4. 🟡 等第一則訊息沒有超時救援（G-10）

按「略過檢查，直接測試」的人（或檢查過了、但 LINE 那邊開關其實沒存到）傳了訊息後，
等待卡會永遠轉圈，精靈不說話，畫面唯一出口是「先跳過測試」。使用者不知道哪裡錯，
最可能的結局是放棄。

**建議修法**：等 30–60 秒沒收到就主動開口列常見原因（Use webhook 沒開／存檔沒按／
回應模式不對），給「回去檢查 Webhook」「再等等」「先跳過」三個出口。
現在的 `Promise.race` 架構加一個 timer 分支就能做。

### 5. 🟡 完成後落地在全 0 的統計頁（G-11，落哪裡＝拍板）

「進入後台」導到 `conversation-stats`——新帳號 KPI 全 0、圖表空白。
剛見證完機器人活起來，第一眼卻是一頁沒有東西的報表，高潮後接冷場。
建議落「對話」頁：他剛傳的那句話就在裡面，敘事接得上。

### 6. ⚪ 小項（G-12）

- `stepAiMode` 的 `apiRetry` 沒給 `skipLabel`：AI 開啟一直失敗時唯一按鈕是「再試一次」，
  只能從右上角「之後再說」逃走（其他步驟都有跳過出口）。
- 草稿模式＋跳過轉真人通知的交互沒提醒：兩個都選的人，客人訊息會有 AI 擬稿、
  但沒有人被主動通知要去送出。建議在第二個跳過發生時補一句。
- `stepWelcomeBack` 進度條 `!ai.enabled` 兩個分支都是 3（dead code）。
- 開場說「一共四步…跟進度條一格一格對得上」，但進度條有五格（第五格「完成」）。

## 確認過沒問題的點（附查證）

- 魔法時刻回顯客人訊息用 `{{ }}` 純文字渲染（`AgentMessageRenderer.vue` highlight 卡），
  客人傳 HTML 不會注入後台。
- 中途離開的人不會誤建第二個帳號：帳號建立後 workspaces 頁不再顯示「我想開始使用」
  迎賓（只在清單為空時出現），回來走健康卡「用聊天引導完成開通」續走。
  入口藏在右下角 FAB 靠紅點指路，現況可接受；`G-4`（首登自動落地開通引導）做完會更順。
- 輪詢成本有界：first-message 4 秒一次、背景分頁不打、收到即停；讀量固定 20＋10 筆。
- 憑證遮罩、不落 log、不進 LLM，與設計釘死一致。
