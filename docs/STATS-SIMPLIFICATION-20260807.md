# 數字與名詞收斂提案（2026-08-07）

> 起因：老闆看昨日摘要卡連問四輪才看懂，接著點出「對話統計＋用量監控名詞太多、
> 使用者要理解的東西太多」，並定調產品主概念：**這是 Agent AI 產品，
> 使用的人要感覺像有一個 agent 一直在服務他。**
> 本文＝盤點＋診斷＋提案。拍板前不動工；拍板後逐項實作並回填狀態。

## 一、現況盤點：使用者到底要面對多少數字

### 三個地方、三套話語

| 介面 | 給誰看 | 數字（含衍生） | 專有名詞 |
|---|---|---|---|
| 小幫手昨日摘要卡 | 每天打開就看到 | 6 個 | 段對話、第一句話是誰回的、轉給真人 |
| 對話統計頁 | 回顧成效 | ~20 個 | 會話、首接、未首接、轉真人**場**、已結束、佔已處理、首接後升級 |
| 用量監控頁 | 額度/成本 | ~25 個 | 則、額度、AI 介入、自己答完、轉給真人**次**、先問清楚、答完又轉真人率、三桶成本 |

合計 **50+ 個數字、三套互相不完全對得上的詞彙**。三個單位（場／則／次）沒有任何地方解釋差別。

### 具體的混淆點（每一條都是真的會被問的）

1. **「轉真人」出現三次、兩本帳**：統計頁數「場」（hasHandoff）、用量頁數「次」（aiUsage.handoffs，
   同一場可轉多次、且只算 AI 觸發的）。刻意不同（見 project 記憶），但使用者面前沒有任何解釋。
2. **「客人對話」（場）vs「客人訊息」（則）**：一場對話含多則訊息。額度賣「則」、統計講「場」，
   兩頁對照看永遠對不起來。
3. **「段」vs「場」**：昨日摘要卡用「段對話」、統計頁用「場」「會話」。同一個東西三個叫法。
4. 「未首接」「佔已處理」「首接後升級」是分析師語言，不是店家語言。
5. 加好友數**完全沒有地方看得到**（資料有存：users.createdAt＋origin='follow' session）。

## 二、診斷

**根因不是數字太多，是「帳本」和「日報」混在一起給使用者。**

- 使用者（店家）每天需要的是 agent 的**工作報告**：昨天發生什麼、我（AI）幫你做了什麼、哪裡需要你。
  ≦ 6 個數字、零專有名詞。
- 統計頁和用量頁是**查帳用**的：老闆月底回顧、對帳額度成本。查帳本來就可以多數字，
  但它不該是使用者「理解這個產品」的入口。
- 現況三個介面平行存在、各講各的話，使用者被迫自己當翻譯。

## 三、提案：以 agent 為中心的三層資訊架構

**第一層＝agent 日報（小幫手卡，每天的入口）**——敘事，不是儀表板：

```
昨日摘要（8/6）
新朋友 +43 位，其中 8 位開口說話          ← 新增（資料現成）
16 場對話，第一句話：AI/機器人 12・你們 4・沒人回 0
這 16 場裡，後來轉給真人的 11 場
（>0 才出現）🔴 N 場沒人回 → 去看　🟠 N 場等超過 30 分 → 去看
```

原則：加起來等於母數的才並排；子集換行加「這 N 場裡」；壞消息才上色、附出口。

**第二層＝兩本帳，各回答一個問題，改用問句當頁名（副標）**：
- 對話統計 →「客人來了多少、誰接住的」（單位：場）
- 用量監控 →「AI 做了多少工、花多少錢」（單位：則/次＋NT$）
頁首各加一行固定說明句：「這裡數的是**場**（一位客人 24 小時內的一段來回）」／
「這裡數的是**則**（AI 每回一句算一則）」。兩頁互相連結對方並講明「單位不同所以數字不同」。

**第三層＝進階/技術細節**（已有雛形：用量頁「僅系統管理員可見」區）：
成本三桶、單價、AI 轉真人「次數」帳、率類指標（答完又轉真人率…）全部收進來。

## 四、加好友要不要記？——建議：記，但記成「新朋友」不是「對話」

- 昨日摘要加一行「新朋友 +N 位，其中 M 位開口」。N＝users.createdAt 當日（8/6 實測 43）、
  M＝origin='follow' 且 hasInbound 當日（8/6 實測 8）。**不進對話數**——沒開口就不是對話，
  混進去統計又灌水（這正是 isPreInboundFollowSession 防的事）。
- 「其中 M 位開口」順便回答了活動成效（加了好友有多少真的來講話）＝現在完全隱形的漏斗數字。
- 統計頁趨勢圖可加「新朋友」一條線（同資料源）。P2。

## 「為什麼 16 場？推播那些不也是開新對話嗎」——口徑說明（給之後的人）

不是。**對話的定義是有來有往**：客人開口了才算一場。加好友／活動推播是系統開了個檔案夾
＋我們單方面塞了一則訊息進去——對方一個字都沒說。8/6 實測 53 個檔案夾裡 37 個屬於這種。
把它們算成對話的後果（正是舊版踩過的坑）：辦一場活動數字就暴漲一次、
「機器人先回」被灌成 90%+、統計從此不能拿來判斷任何事。
所以拆成兩個數字各自誠實：**新加好友 43 位**（進來多少人）＋**16 場對話**（多少人真的開口）。
