## 當時看到什麼

**系統今天對一位客人知道的事**（`UserDoc` ＋ `ConversationDoc` ＋ `userTags` 逐欄查證）：

- 有：LINE 名字與頭像、封鎖狀態、標籤（來源分 manual/import/rule/system 四種）、
  腳本 collect 收進來的自由欄位（`attributes`，key/value）、完整對話紀錄、
  按過的按鈕（customer_action）、最後來訊時間（`lastInboundMessageAt`，08-19 起）。
- 沒有：買過什麼、花了多少（「客單價」全 repo 只出現在 `index.vue:285` 的示意圖）、
  生日、加好友來源、店家手寫備註。
- **收進來看不到**：`attributes` 在 `app/pages/admin`＋`app/components/admin` 底下
  **零個引用**——腳本問到的答案沒有任何一頁顯示（`G-6` 的根）。

**CRM 四步的現況**（認識 → 分群 → 開口 → 回看）：

| 步驟 | 有 | 缺 |
|---|---|---|
| 認識客人 | LINE 檔案、標籤、腳本收答案、對話全文 | 購買／生日／來源；收進來的答案看不到（`G-6`） |
| 分群 | 推播受眾＝全部／標籤／既有名單／貼名單（`BroadcastAudienceSource` 四種） | **動態維度只有標籤一種**；不能按屬性、按「多久沒來」分 |
| 開口 | 排程推播、節慶提醒（`C-54`）、腳本、AI 回覆、圖文選單、加好友歡迎（`C-56`） | 「它先開口」只到提醒老闆，還沒到代擬與名單（`C-55`） |
| 回看 | 推播成效報表（LINE 開封數＋追蹤連結點擊，`broadcast/[id]/report`） | 推完之後「誰回來講話」沒有名單層級的回看；無逐人頁可追單一客人歷程 |

**關鍵結構判斷：標籤是全系統唯一的分眾入口。** 所以任何新資料（生日、沉默天數、
AI 判斷的意向）只要**做成標籤**，推播端一行都不用改就能用。這是本報告排優先序的
核心邏輯——先把「什麼都變標籤」的路修好，再談高級功能。

## 兩個發想的評估

### 發想一：AI 讀對話自動貼標（`D-24`）——本報告最推薦的一條

**為什麼是槓桿**：①對話是這個產品**獨有**的資料（電商工具有訂單、我們有客人親口說的話）
②標籤是現有唯一分眾入口，貼上去馬上能推播，不用動下游 ③首頁「顧客貼標」卡從半真變全真
④它是發想二的前提——AI 觀察完要能講出「發給誰」，手上得先有名單。

**可行性查證**：AI 管線現成；對話 session 有明確的關閉點可掛
（`conversation-session.ts`）；`UserTagSourceType` 已有 manual/import/rule/system
四種來源，加一種 `ai` 即可；「建議→採用／忽略」的收件匣模式在 AI 學習迴圈做過一次
（knowledgeSuggestions），介面模式可重用。

**設計上要拍板的一題**：建議式（AI 先列建議、人按確認才貼）vs 全自動（直接貼、
記來源可撤）。**建議 Phase 1 走建議式**——貼錯標籤的下游是「推錯人」，而
🔴 紅線原則（08-14 拍板）是對客人說話最後一顆按鈕留人；標籤本身不對客人說話，
但它決定誰收到推播，第一版先讓人看過比較穩。跑順了再開全自動＋抽查。

**成本控制**：對話結束才跑一次（不是每則訊息）、用小模型、只回標籤 ID 白名單內的值
（⛔ 模型不生 ID，沿用既有原則）。估 4–6 天（Phase 1 建議式，含收件匣 UI）。

### 發想二：AI 觀察給行銷建議（`D-25`）——方向對，但別當一個新功能做

它就是 `C-55`（節慶提案）的靈魂，建議收成**同一條路線分三階**，不另開戰場：

1. **第一階（已上線）**：`C-54` 節前 7/3/1 天提醒＋切角建議——「它先開口」已經開始。
2. **第二階（洞察週報，3–5 天）**：每週把「這週 23 人問過禮盒」「上月有講話、
   這月沉默的有 41 人」這種觀察塞進現有每日／週訊息管道。**前提是發想一**：
   沒有 AI 貼標，觀察只能講現象，講不出「名單在這裡、要不要發」。
3. **第三階（＝`C-55`，5–8 天）**：提案卡（分客群＋代擬訊息＋一鍵採用）。
   維持 08-21 評估的前提：`C-54` 要先實機收過一則。

⛔ 不要跳過第二階直接做第三階：提案卡的信任要靠「它的觀察常常是對的」累積，
先用低風險的週報養信任，再給它「一鍵發出去」的權力。

- **客人單頁（`G-6`）**：好友列表點人 → 側欄個人頁（LINE 檔案＋userTags 含來源＋
  `attributes`＋最近 session 摘要＋最後來訊）。套 AdminShell 共用外殼；
  後端一支單人詳情端點，按 doc id 直讀不掃 collection。AI 貼標的採用／忽略之後放這頁。
- **AI 貼標（`D-24`）**：掛 session 關閉點、每場跑一次小模型；輸入＝該場對話＋工作區標籤清單，
  輸出＝白名單內的標籤 ID（⛔模型不生 ID）。建議寫進收件匣（重用 knowledgeSuggestions 模式），
  採用才貼、來源記 `ai`、可撤。跑順再議全自動。
- **「N 天沒互動」標籤**：每日排程（掛現有 maintenance 管道）掃 `lastInboundMessageAt` 超過 N 天
  → 貼 system 標籤；客人來訊即摘。游標分頁不整批掃（⛔讀取費）。
  ⚠️ 該欄位 08-19 起才寫、刻意不回填——舊客第一批抓不到，隨時間自然補齊，
  同時避免部署當下整排被貼標（同紅點不回填的理由）。N 可設定，預設 60。
- **生日＋壽星（`C-57`）**：正規化存法（單一欄位、只存月日）；腳本 collect 收到生日轉格式寫入、
  單頁可手填；每月 1 號排程貼「本月壽星」、月底摘。走貼標不動推播端（08-21 評估既定路線）。

- **洞察週報（`D-25` 第二階）**：週聚合「AI 標籤主題排行＋沉默客數」，
  走 C-54 同一條 LINE 訊息管道；每條觀察附後台名單深連結。
- **提案卡（`C-55`）**：串現成四零件（節慶表／標籤分眾／排程推播／LLM 擬稿）＋
  提案資料模型（可改、可拒、記口味）；送出前留人按最後一顆（🔴紅線）。
