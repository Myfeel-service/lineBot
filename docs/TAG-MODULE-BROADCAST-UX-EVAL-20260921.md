## 一句話結論

**三頁分開本身不是錯——錯的是三頁之間沒有路。**
標籤是「名單上的記號」、模組是「要回什麼」、推播是「什麼時候對誰發」，三種東西分三頁放，
競品（Omnichat）也這樣分。但我們的三頁之間：**沒有一條可以點的連結**（推播頁與模組頁
零連結）、**沒有一個地方可以就地建標籤或建模組**（標籤只有標籤頁能建）、
**沒有任何地方看得到「誰用了誰」**（一顆標籤被哪個模組貼、哪則推播用；一個模組會在哪些時候發出），
**全站只有兩支導覽裡各一句話講過三者的關係**。

而正式庫證明這條鏈不是偶爾用，是**主力**：MYFEEL 16 則推播裡 14 則按標籤分眾、13 則內容是模組；
8 個活動全部同時綁了標籤＋模組。**每上一檔新商品，操作的人要跨四頁、照固定順序、至少來回兩趟**——
MYFEEL 已經這樣做了 8 次。「要熟悉一陣子」熟悉的不是功能，是**這條沒有人畫出來的路線**。

## 一、先用白話講清楚這四樣東西（以及為什麼會搞混）

| 東西 | 它是什麼 | 它**不**管什麼 |
|---|---|---|
| 標籤 | 貼在客人身上的記號（「問卷 - 乾淨方MAX」「客服 - BOYA」） | 不會對客人說話 |
| 機器人模組 | 一組要回給客人的訊息（最多 5 則，可帶按鈕） | **不知道自己什麼時候會被叫出來**——模組上沒有任何「觸發」欄位 |
| 推播 | 主動把「一段文字」或「一個模組」發給「全部／某幾顆標籤的人／一份名單」 | 發完不會貼標、點了不會貼標 |
| 活動標籤 | 一條連結：客人點了、加好友，系統**自動貼標**＋（選填）**發一個模組** | 它不發推播；名字叫「活動標籤」但它其實是「入口」 |

所有困惑的根在第二列：**模組自己不知道什麼時候會發出**。叫出一個模組的路有七條，
分別設在七個不同的頁面（自動回應的關鍵字／加好友、圖文選單、推播、活動、客服預存、
另一個模組的按鈕、用戶輸入卡片的下一步），而模組頁只用一行灰字提到其中一條
（[flow.vue:186](../app/pages/admin/%5BworkspaceId%5D/flow.vue#L186)：「關鍵字觸發請到「自動回應」設定」，**不是連結**）。

## 二、第一次的人會怎麼卡（八個情境，都有程式依據）

### 情境 A｜上一檔新商品，要跑完「問卷 → 加好友貼標 → 之後推播」

這是 MYFEEL 真的在做的事（第三節的資料）。今天的走法：

1. 到「**標籤管理**」建「問卷 - X」。想讓模組按鈕再貼一顆「客服 - X」，要在這裡**再建一顆**。
2. 到「**機器人模組**」建一個模組（歡迎訊息＋按鈕）。按鈕若要貼標，下拉只列**已存在**的標籤——
   剛才忘了建就得放棄這張還沒存的表單、回第 1 步。
3. 到「**活動標籤**」建活動，選標籤、選模組。**還要先在「組織與 LINE」設好 LIFF**，否則建立鈕是灰的。
4. 隔週要推新品，到「**推播**」建一則，選「依標籤篩選」勾「問卷 - X」，內容選「觸發機器人模組」再挑模組。

**四頁、順序固定、任何一步發現缺零件就要中斷回頭。** 沒有任何一頁告訴你下一步去哪。

### 情境 B｜模組編輯器裡按下「啟用貼標」，下拉是空的

新帳號沒有標籤。模組頁的貼標下拉（[FlowActionEditor.vue:109-115](../app/components/flow/FlowActionEditor.vue#L109-L115)）
空了就是空的，**沒有一個字告訉你去哪建**。推播頁的「依標籤篩選」、圖文選單的貼標也一樣。
對照組：活動標籤與客服預存兩頁在空狀態**有**「尚無標籤，請先前往「標籤管理」建立」的連結
（[campaigns.vue:352](../app/pages/admin/%5BworkspaceId%5D/campaigns.vue#L352)、
[support-presets.vue:139](../app/pages/admin/%5BworkspaceId%5D/support-presets.vue#L139)）。**同一個後台兩套。**

### 情境 C｜模組建好、按了儲存，然後呢？

什麼都不會發生。模組頁沒有「這個模組會在哪些時候發出」的資訊，沒有使用次數、沒有被引用數。
[flow.vue](../app/pages/admin/%5BworkspaceId%5D/flow.vue) 全檔**零個**可點的站內連結（grep `NuxtLink|navigateTo|router.push` 無結果）。
唯一講「什麼時候會回」的是導覽最後一步（[tutorial-topics.ts:771](../app/utils/tutorial-topics.ts#L771)），
而導覽是選跑的、那一步是純文字。

### 情境 D｜推播想發給「問過出貨」**且**「買過東西」的人

做不到。推播的標籤篩選只有「或」（[broadcasts.vue:149-154](../app/pages/admin/%5BworkspaceId%5D/broadcasts.vue#L149-L154)），
畫面老實寫了「想寄給「兩個條件都符合」的人，目前要先到「好友」頁篩出那批人」——
但**好友頁篩出來之後沒有「推播給這些人」的按鈕**（批次列只有加標／移標／取消選取，
[users.vue:54-58](../app/pages/admin/%5BworkspaceId%5D/users.vue#L54-L58)）。這句指路指到一條死路。
推播頁本身也是**零連結**（連「好友」兩個字都不能點）。

### 情境 E｜想知道一顆標籤被誰用；或停用了一顆標籤

標籤頁只有「好友數」，**沒有「用在哪」**（哪個模組貼它、哪則推播用它、哪個活動貼它）。
全 repo 只有一支反查（`broken-module-refs.ts`），而且只反查「模組被刪」這一種，
標籤明文「原樣保留」不查。後果：
- 停用一顆標籤 → 模組／活動／推播裡存的還是它的 id；下拉只載入啟用中的標籤，畫面會顯示一串原始代碼而不是名字。
- 推播受眾解析（`server/utils/audience.ts`）**不看標籤狀態**——按已停用標籤建的推播照樣寄出去。

### 情境 F｜同一樣東西三個名字

| 同一個東西 | 側欄 | 頁標題 | 小幫手帶路 | 教學清單 |
|---|---|---|---|---|
| 活動 | 活動標籤 | 活動貼標 | 活動 | 活動貼標（名單分眾） |
| 模組 | 機器人模組 | 機器人模組 | 對話模組 | 認識機器人模組 |
| 好友 | 好友 | — | 好友名單 | 管理好友與貼標 |

標籤頁的按鈕叫「新增」、空狀態叫人按「新增標籤」。第一次的人在四個地方讀到四種名字，
會以為是四樣東西。

### 情境 G｜教學的順序反了，而且小幫手帶不了路

「經營工具」教學清單的順序是**圖文選單 → 推播 → 標籤 → 活動 → 好友**：先教「發一則推播」
（第三步叫你用標籤分眾），再教「建立好友標籤」。全站唯一講三者關係的兩句話——
「貼了標籤，之後推播就能只發給某群人、活動也能自動貼標歸類」（[tutorial-topics.ts:1123](../app/utils/tutorial-topics.ts#L1123)）
與總覽導覽第二步——都藏在導覽裡，頁面本身不講。
小幫手的帶路白名單（`shared/agent-destinations.ts`）**沒有標籤頁**；它能查標籤人數、能建推播草稿，
但**不能建標籤、不能建模組、不能建活動**。

### 情境 H｜順手抓到：「歡迎模組」這顆系統模組沒有任何程式會自動發它 🔴

導覽第二步說「它在客人加好友的當下自動發第一組訊息……系統內建，你只要編內容」
（[tutorial-topics.ts:741-743](../app/utils/tutorial-topics.ts#L741-L743)）。
但 `server/` 裡 `systemModuleId(..., 'welcome')` **沒有任何執行路徑讀它**（只有 `live_agent` 在轉真人時會被讀），
加好友歡迎走的是「自動回應 → 客人加好友時」的腳本（`handler.ts` 的 `runFollowWelcomeScript`，08-22 `C-56`）。
**第一次的人照導覽把歡迎模組編好、等客人加好友——什麼都不會發生。** 這條要另外拍板（第七節第 4 題）。

## 三、線上實況：這條鏈是主力，不是偶爾用（MYFEEL 唯讀盤點，2026-09-21）

| 東西 | 數量 | 彼此怎麼連 |
|---|---|---|
| 標籤 | 39 顆（全部啟用；13 顆設「AI 直接貼」、26 顆不用 AI） | — |
| 機器人模組 | 71 個（69 自建＋2 系統） | 4 個有按鈕開貼標；**52 個**有按鈕指向另一個模組 |
| 推播 | 16 則（13 完成、2 失敗、1 取消） | **14 則按標籤分眾**、2 則匯入名單、0 則全部好友；**13 則內容是模組**、3 則純文字 |
| 活動 | 8 個（全部啟用） | **8 個都同時綁標籤＋模組** |
| 圖文選單 | 2 張 | ⚠️ 貼標與模組指向在存檔時被**編碼進按鈕字串**（`richmenu.vue` 的 `encodeTriggerModule`），本次沒解碼，**不知道** |
| 客服預存 | 10 則 | 0 則開貼標 |
| 貼在客人身上的標籤 | 6,066 筆 | 約 4,950 筆（82%）來自**活動連結加好友**；667 筆（11%）模組按鈕；185 筆（3%）模組內網址點擊；259 筆（4%）AI 判斷；手動 4 筆 |

**三個解讀：**

1. **連結在資料裡存在、在畫面上不存在。** 推播幾乎全靠標籤（14/16）、內容幾乎全是模組（13/16）、
   活動全部綁模組（8/8）——使用者已經把三樣東西當一件事在用，後台卻要他分四頁放。
2. **標籤的命名洩漏了心智模型。** 推播用到的 5 顆標籤全是「問卷 - X」與「MYFEEL之夜」，活動貼的 8 顆全是「問卷」類，
   模組按鈕貼的是「客服 - X」。使用者腦中的單位是**「一檔商品／一場活動」**，
   每檔＝一顆問卷標籤＋一顆客服標籤＋一個模組＋一個活動＋（之後）一則推播。後台的單位是「一種東西一頁」。
   **「要熟悉一陣子」＝要學會把腦中的一件事拆成四種零件、記住放哪、記住順序。**
3. **會自動貼標的路幾乎沒被用**：客服預存 10 則裡 0 則開貼標、模組 71 個裡 4 個有按鈕貼標
   （圖文選單那兩張本次沒解出來，不算）。要嘛是不知道有這功能，
   要嘛是「要先去別頁建標籤」這一步把人擋掉了。兩種都指向同一個修法：就地建標籤。

## 四、根因是三個，不是「頁面太多」

| # | 根因 | 造成的情境 |
|---|---|---|
| R1 | **模組沒有「什麼時候被叫出來」的資料**（`flows` 文件沒有 trigger 欄位，七條入口各存在七個地方） | C、H |
| R2 | **標籤是三頁共用的名詞，但只有一頁能造名詞**（`/api/tag/create` 全 app 只有 `tags.vue` 兩處呼叫） | A、B |
| R3 | **沒有「一檔活動」這個層級**——使用者心中的一件事，在系統裡是四筆彼此不知道對方存在的資料；反查只做了「模組被刪」一種 | A、D、E、F、G |

把三頁合成一頁解不了 R1～R3 任何一條（模組 71 個、推播 16 則、標籤 39 顆塞同一頁只會更難找），
所以下面的建議**不動頁面切分、不動資料模型**，動的是「頁與頁之間的路」與「建立的順序」。

## 五、建議：分三層，先接路、再做精靈、最後才談自動化

### 第一層｜把路接起來（不加新概念，約 3 天）

| # | 做什麼 | 解哪個情境 | 估 |
|---|---|---|---|
| 1 | **就地建標籤**：所有標籤下拉加一顆「＋ 新標籤」，開小視窗填名稱／分類就建好、建完自動選中。做成一個共用元件，接進模組、推播、活動、圖文選單、客服預存、自動回應六處。英文代號**自動生成不顯示**（見第七節第 3 題） | A、B | 0.75 天 |
| 2 | **空狀態一律有出口**：推播、模組、圖文選單三頁補「尚無標籤，去建」「尚無模組，去建」（活動、客服預存、自動回應已有）；帶 `?return=` 回來 | B | 0.25 天 |
| 3 | **模組頭上那行灰字改成反查列表**：「這個模組會在這些時候發出：自動回應 N 條、圖文選單 N 格、活動 N 個、推播 N 則、其他模組的按鈕 N 顆」，每項可點過去；**0 個時**顯示「還沒有任何地方會叫出這個模組」＋按鈕「去自動回應設定關鍵字」。`broken-module-refs.ts` 已掃四種來源，補推播與客服預存兩種即可共用 | C | 0.75 天 |
| 4 | **標籤頁加「用在哪」欄**：N 個模組貼／N 則推播用／N 個活動貼；停用前跳警告「還有 N 個地方在用」。推播受眾解析同時改成跳過已停用標籤 | E | 0.5 天 |
| 5 | **好友頁批次列加「推播給這 N 位」**：帶進推播頁、受眾自動選「匯入名單」並填好——推播的 `import` 型別現成，後端一行不用改。順便解掉「兩個條件都符合」那條死路 | D | 0.25 天 |
| 6 | **名詞統一**：側欄＝頁標題＝小幫手＝教學清單；「新增」與「新增標籤」對齊；小幫手帶路白名單補上標籤頁 | F、G | 0.25 天 |
| 7 | **教學順序改成 標籤 → 活動 → 推播**，並把「貼了標籤，之後推播就能只發給某群人、活動也能自動貼標」這句從導覽搬到三頁頁首的常駐說明 | G | 0.25 天 |

### 第二層｜以「一檔活動」為單位的建立精靈（一個新概念，3–4 天）

第三節證明使用者的單位是「一檔」。給他一個入口叫「**新活動**」（放在活動標籤頁「新增」旁邊，不取代既有表單），一頁走完：

1. 這檔叫什麼（例：「宜米製冰機」）
2. 客人加好友要貼什麼標籤——**預設幫他建**「問卷 - 宜米製冰機」，可改可加
3. 客人加好友後要看到什麼——就地建一個模組（文字＋按鈕），或選既有的
4. 拿到活動連結（LIFF 沒設就在這裡提示去設，跟現在一樣）
5. 完成頁：「之後要推播給這群人 → **建一則推播草稿**（已幫你選好標籤與模組）」

底層仍是四筆資料、四支既有端點，精靈只負責順序與預設值。**不動資料模型、不加側欄項目**
（08-22 一致性拍板）。這一層直接對應 MYFEEL 重複做了 8 次的那條路。

### 第三層｜把迴圈關起來（等前兩層跑順再說）

- 推播發完自動貼「已收到〈推播名〉」標籤（Omnichat 有；`userTags.sourceType='system'` 現成）——解「這群人上次收過什麼」。
- 推播的按鈕開貼標：`AdminAreaActionEditor` 的 `enableTagging` 一個 prop，推播頁沒傳。
- 小幫手「用講的建一檔活動」：接 `D-58` 盤出來的「建立類幾乎不在任何批次」缺口，等第二層的精靈端點出來再接。
- `automationRules`（型別裡「Phase 3 預留」的 follow／click → add_tag／send_broadcast）**這一輪不做**。

## 六、競品怎麼做（只講跟這題有關的）

| | 我們 | Omnichat（官方教學文件） | LINE 官方後台 |
|---|---|---|---|
| 標籤／模組／推播分頁 | 分 | **也分** | 標籤在聊天、受眾在群發 |
| 標籤要先建好才能在別頁選 | 是 | **也是**（模組按鈕可貼最多 5 顆，須預先存在） | 手動貼標為主 |
| 推播內容可選模組 | 可（但編輯器不預覽模組內容） | 可，**選了會顯示模組預覽** | 不適用 |
| 推播發完自動貼標 | 無 | **有**（「此標籤僅表示這群人被成功推播」） | 無 |
| 受眾條件 | 標籤「或」 | 自訂條件可組合 | 受眾要 ≥100 人才能篩 |
| 模組裡用標籤分流 | 無 | 有「條件分流卡片」 | 無 |

結論：**分開不是問題，差在「連結」與「預覽」**。Omnichat 同樣要人先去建標籤，但推播頁看得到模組長什麼樣、
發完會自動留下記號。我們該補的是路，不是合併。

## 七、要拍板的四題

1. **第一層七條照做？** → 建議**做**，全部是接路、零新概念，約 3 天。
2. **第二層「一檔活動」精靈做不做？入口放哪？** → 建議**做**，放活動標籤頁「新增」旁，
   叫「用精靈建立」，**不取代**既有表單（熟手照舊）。
3. **就地建標籤時，「英文代號建立後不能改」怎麼處理？** → 建議：就地建立時代號**由系統自動生成、不顯示**
   （名稱轉拼音或英數；撞名加序號），規則本身不變、只是不再要求使用者填。
   要拍板是因為它動到標籤頁上白紙黑字的既有規則。
4. **「歡迎模組」這顆系統模組怎麼處理？**（情境 H）二選一：
   a) 讓它真的在加好友時自動發（沒有 follow 腳本時當預設）
   b) 拿掉這顆系統模組，導覽改講「加好友歡迎在自動回應 → 客人加好友時」
   → 建議 **b**：08-22 已拍板歡迎走腳本（能收資料、貼標、轉真人），再養一顆只會發訊息的歡迎模組是兩套。

## 八、刻意不做（以及為什麼）

- **不把三頁合併成一頁**：解不了三個根因，只會把 2,805 行的模組頁變成兩倍。競品也分頁。
- **不改資料模型**：標籤仍是全系統唯一分眾入口（08-22 CRM 評估的核心邏輯），新東西做成標籤就能推播。
- **不新增側欄一級項目**：08-22 一致性拍板；精靈掛在既有頁面上。
- **不這一輪做 AND／NOT 分眾介面**：好友頁篩選 → 「推播給這 N 位」那條路先解掉多數需求，之後看有沒有人真的要。
- **不讓小幫手自動建標籤、自動生 ID**：維持 `D-24` 建議式與「模型不生 ID」原則；第三層才接、且只到草稿。
- **不做 `automationRules`**：那是把三頁變成「規則引擎」，在路都還沒接好之前是跳級。
- **不重寫教學**：第一層第 7 條只是調順序、搬一句話。
