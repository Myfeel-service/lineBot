## P0 — 會直接傷害客人體驗,上線前必修

### 1. 反問按鈕點下去之後,答非所問(原始問題丟失)
- 問「威技除濕機的水箱多大?」→ 反問哪一款 → 點選項 → 回**操作面板按鍵清單**。
- 問「噪音大概幾分貝?」→ 反問 → 點「威技除濕機」→ 回「品牌 NWT 威技,型號 WDH31B16E,110V 電壓」。
- 根因:`handler.ts` 反問 followup 把**選項卡片標題**當新 query(`query = match.title`),原始問題只留在 history,檢索與作答都圍著卡片標題轉。兩次重現,正式 LINE 鏈路同邏輯。
- 修法方向:followup 時把原始問題(或 standaloneQuery)與選到的產品/卡片**合成**檢索 query,作答 prompt 明示「客人原本問的是 X」。

### 2. 同一台機器被當成兩台:產品別名分裂
- 「上好ㄟ抽取式除濕機」=「NWT 威技 16L WDH31B16E」同一台,但產品索引同時存在「上好ㄟ抽取式除濕機」「NWT 威技 除濕機」「NWT 威技 新一級能效 16L 高效抽取型除濕機」三個名字。
- 實測災情:問出貨時間,AI 回「上好ㄟ 5/15 已出貨…NWT 威技 16L 預計 8 月底出貨」——把同一台講成兩台、出貨時間互相矛盾(兩張卡資訊也真的衝突:最新消息卡 vs 客服 gsheet 卡)。反問時也出現「威技除濕機 / 上好ㄟ除濕機」要客人二選一。
- 其他 alias 群:粒粒安飛利浦×2、W1 REGEN×2(含《》變體)、Poketomo×2、GPLUS×2。
- 修法方向:產品索引建立別名歸一(canonical name + aliases),卡片衝突時以較新來源為準或人工對齊。

### 3. 過期的時效性內容照答不誤(prompt 沒帶今天日期)
- 問「零水鍋募資什麼時候結束?」→ 答「募資期間到 2026 年 7 月 12 日晚上 11 點 59 分喔」——**已過期 19 天**,當現在式講,也不說「已結束」。
- 同類地雷卡:「SHARP森呼吸NEXT折扣活動」(折扣碼 NEXT300)、「兩全奇美燈品牌感恩回饋價」(『現在不需要折扣碼』)、「Cheerble 濾芯集資期間加購 499」、「上好ㄟ出貨進度 5/15」——全是行銷快訊,無過期機制。
- 修法方向:(a) answer prompt 注入台灣時區今天日期+「過期資訊要說明已結束」;(b) 時效性來源(最新公告/Progress/最新消息)給卡片加有效期或定期下架。

### 4. 生產開關組合處於危險狀態:anyText 規則攔住一切,但 AI 已設定為直接自動回覆
- handler 順序:敏感詞 → 進行中腳本 → **自動回覆規則** → 腳本啟動 → AI 保底。MYFEEL 現有 **1 條啟用中的 anyText 規則**,所以目前客人任何問題都吃罐頭回覆,AI 不會出手(敏感詞除外,會直接走 AI 轉真人)。
- 但 `aiSettings`:`enabled=true`、`replyMode=auto`(不是 draft!)、`handoffNotify.enabled=false` 且 `lineUserIds=[]`。
- 意即:**哪天把 anyText 規則關掉,AI 立刻直接對客人講話,而轉真人一個通知都發不出去(黑洞)**。上線程序應為:先設轉真人通知+改 draft 演練 → 再關規則。
- 另 `shopUrl` 仍空(見 P1-5)、`serviceHours` 關(有意)。

## P1 — 高頻場景體驗差

### 5. 價格問題全軍覆沒
「除濕機多少錢?」「多少錢?」「哪邊便宜?」全部 no_grounding 轉真人。知識庫**沒有任何價格卡**,而 prompt 本來有「價格問題引導去 shopUrl」的機制,但 `shopUrl` 沒設定,整條路死掉。價格是電商第一高頻問題。修法:設 shopUrl(成本最低),或知識庫補「怎麼查價格」卡。

### 6. 比較題 4/4 全滅
「GPLUS 6L 跟 12L 差在哪」「GPLUS 12L 跟威技 16L 哪台適合房間」「W1 REGEN 跟 ULTRA 差在哪」「跟 GPLUS 12L 比哪台安靜」→ 全部轉真人。規格卡其實存在(A07 檢索就撈到過「GPLUS除濕機12L產品規格」),但 compare 路徑撈回來的是長期存放/保固/故障排除卡。比較是導購核心場景。

### 7. LLM 過度保守誤殺:卡片有答案仍拒答
「飛利浦電子鍋內鍋是什麼材質?會不會沾鍋?」→ 檢索命中「內鍋材質與特性」(0.828),卡片明寫「**316不鏽鋼、無化學塗層**」,LLM 仍回 hasInfo=false 轉真人。0623 客服實測已知的「過度保守」在正式庫重現。同型:「小獴友是什麼?」(新客第一問)也拒答。

### 8. 越界問題一律轉真人 → 真人客服會被雜訊淹沒
天氣、寫詩、prompt injection×2、競品比較(Panasonic)、沒賣的品類(加濕器)→ 全部 no_grounding **轉真人**。好消息:injection 沒有洩漏 system prompt、沒被帶偏。壞消息:任何路人亂丟一句都會排進轉真人佇列。應改為「明顯超出範圍 → 禮貌拒答+說明能答的範圍」,不進轉真人。

### 9. 反問選項品質差(卡片級選項、同義重複、混入不在售商品)
- 問「能不能放浴室」→ 選項「使用注意事項 / 擺放環境與空間限制 / 擺放環境要求」(後兩個幾乎同義,來自 6L/12L 兩本說明書的重複卡)。
- 問「有沒有折扣碼」→ 選項「SHARP森呼吸NEXT / 奇美燈品牌 / Cheerble飲水機濾芯」——森呼吸NEXT 甚至不在產品索引 20 名單內;三個選項層級混雜。
- 問「保固怎麼登錄」→ 10 個選項,含「商品保固登錄方式 / 產品保固登錄與期限 / 商品保固註冊流程」三張通用同義卡,label 客人無法區分。
- 修法方向:反問選項應聚合到**產品層**,同產品/同義卡去重;無主卡不進選項。

### 10. 一句兩問:漏答或強迫二選一
- 「Poketomo 訂閱多少錢?**不訂閱能用嗎?**」→ 只答價格,第二問無視(卡片其實有寫:必須訂閱才能對話)。
- 「咖啡機怎麼清潔?零水鍋還買得到嗎?」→ 反問要客人二選一。
- intent router 的 `subQuestions` 機制存在,但沒有發揮。

15. **答非所問**:「臥室能用嗎?噪音大不大?」→ 回噪音大時的故障排除法,沒回答噪音水準;「一天除幾公升」→ 回「容量是 16 公升」(對,但客人可能理解成水箱容量)。

17. **生氣客訴**轉真人正確,但 handoffReason 記為 no_grounding(統計口徑會歸錯類)。
