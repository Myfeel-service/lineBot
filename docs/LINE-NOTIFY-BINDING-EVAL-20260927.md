# 綁 LINE 收「每日摘要」與「沒人接手提醒」：進後台之後那一段的評估（2026-09-27）

> 決策紀錄，寫完即凍結。狀態一律看 `docs/STATUS.md` 的 `D-103`。
> 起因：老闆問「目前綁定 LINE 變成會收到每日狀態跟未回覆提醒的流程，評估是否有優化的空間，主要是進入後台後的流程」。
> 建議做法已畫成示意頁：artifact `DCNtvHLkws7NRiMmDXXqeZ` **v1**（上方三個情境可點：老闆自己加／邀同事／有人收不到，下方是整段流程圖）。
> 開帳精靈裡「用手機測試＋按『是我』」那一段（`D-101`／`C-250`③）不在這次範圍，只在它跟後台接得上、接不上的地方提到。

## 一、結論

**「綁好 LINE」跟「會收到通知」現在是兩件事，要在兩頁各做一次，而且做完沒有任何回音。**
建議收成一件事：**一個頁面（設定 → LINE 通知）、手機掃一下就加進來、當場收到一則確認**；
收不到的人那一列會自己變黃、寫出原因。

## 二、今天的樣子

### 一份名單管五種通知

所有會傳到手機的通知都只看同一份名單 `aiSettings.handoffNotify.lineUserIds`，外加一顆總開關 `enabled`：

| 通知 | 程式 | 什麼時候傳 |
|---|---|---|
| 客人找真人 | `server/utils/ai-handoff-notify.ts:58` | 模式「每次都通知」時當下傳 |
| 沒人接手提醒 | `server/utils/cron-maintenance.ts:792` 起 | 超過設定分鐘數沒人回（「只通知沒人接手的」模式下這是唯一一則） |

| 出大事 | `server/utils/cron-maintenance.ts:1477` | 9:00–21:00，同一件事一天一次 |

這份名單在畫面上叫「**轉真人通知**」，放在「**AI 設定**」裡（`app/pages/admin/[workspaceId]/ai-settings.vue:187`）。

## 三、卡在哪

1. **綁好了不會收到。** 成員管理綁完，還要去 AI 設定再勾一次；兩頁之間沒有任何連結提醒。開帳「是我」那條會自動加，後台這條不會，兩條路做完的結果不一樣（`C-263`）。
2. **綁的動作要兩個人互傳。** 管理員產碼 → 用別的管道把連結傳給同事 → 同事點 → 管理員按「我完成了」手動重整（`members.vue:284`，後台收不到即時訊號）。碼 10 分鐘過期。客服自己想收，**沒有地方可以自己綁**：產碼要管理員（`line-bind-code.post.ts:12`），「是我」只在開帳精靈裡、也要管理員。
3. **選人器列的是客人。** AI 設定與小幫手都從「官方帳號好友清單」挑人，清單上絕大多數是客人。挑錯一位，**那位客人就會收到其他客人的名字、原話與摘要**（通知內容見 `ai-handoff-notify.ts:109`）。小幫手那支還會把名單整份換成挑的那一位（`agent-guides.ts:399` 寫 `lineUserIds: [picked.id]`），名單原本有人但總開關關著時，其他人會被洗掉。
4. **綁完到第一則之間沒有回音。** 最快也要等到隔天摘要時間（週末休息的帳號可能是下週一），或下一位客人找真人。這段時間沒有任何東西證明「真的會收到」。
5. **送不到沒有人知道。** 名單上的人封鎖或退好友時，`users.isBlocked` 有被標起來（`server/utils/handler.ts:788`），但通知不看它；推播失敗只寫一行 log（`ai-handoff-notify.ts:125` 等五處）。小幫手的「沒有人會收到轉真人通知」只看名單是不是空的（`server/utils/workspace-alerts.ts:656`）——名單上兩個人都封鎖了，這顆提醒也不會亮。
6. **收到了點不回去。** 每則都只寫「請至後台『對話』頁回覆」「→ 後台『對話』」，沒有連結。⚠️ 如果加連結要注意：在 LINE 裡點連結會開 LINE 內建瀏覽器，而後台是 Google 彈窗登入（`app/composables/useAuth.ts:28`），Google 不讓內建瀏覽器登入；連結要帶 `openExternalBrowser=1` 讓它開到手機的 Safari／Chrome。
7. **名字跟位置對不上。** 同一件事叫「轉真人通知」（AI 設定、小幫手）、「LINE 通知」（成員管理那一欄）、「早上的摘要」（開帳）。它放在「AI 設定」裡，但它管的是人跟手機：純真人客服的帳號、沒有 AI 設定權限的客服，都不會想到去那裡找（`D-36`③ 當時已經注意到純真人帳號的問題）。
8. **總開關跟名單是兩個東西。** 名單上有人但開關關著＝全部不傳，而畫面上看起來名單還在（`C-265`④ 為這個狀態特別補了 `off`）。

### 為什麼後台不沿用開帳的「加好友＋按『是我』」

開帳那一刻帳號是新的，加好友的幾乎只會是他自己，而且加好友那一下同時測通了連線（`D-101`）。後台不一樣：
- 已經在營運的帳號，等待的那一分鐘裡**真的客人**也在加好友、傳訊息，「是你嗎？」會一直問到陌生人。
- 同事多半早就是官方帳號好友，加好友事件不會再來，最後還是要傳一句話。
- 連線早就通了，不需要順便測。

所以後台用「掃 QR → 訊息已打好 → 按送出」：訊息裡帶著只屬於他的碼，不會認錯人，也不用按確認。對他來說兩邊都是「拿手機掃一下」。

## 五、刻意不做的

- **每人分開選收什麼**（例如客服只收找真人、老闆只收摘要）：2026-08-06 拍板「訂閱矩陣先不做」，照舊。新頁的每一列留了位置，之後要加是在那一列多兩顆開關，不用再改版面。⚠️ 要留意的變化：開帳「是我」之後老闆一定在名單上，預設模式「每次都通知」下，老闆的手機每位找真人的客人都會響。小店老闆多半就是客服本人，暫時不構成問題；有第二位客服的帳號出現抱怨時再拿出來談。
- **在 LINE 裡直接回客人**：通知裡放連結（⑦）先解決「點不回去」；在 LINE 回覆要另一套身分與權限設計，不在這次。
- **一鍵「傳一則測試」**：② 的確認訊息與每一列的「上次送達」已經回答「收不收得到」，再加一顆按鈕只是多一個要解釋的東西。

## 六、拍板題

1. **開新頁「設定 → LINE 通知」，把 AI 設定裡「轉真人通知」整區搬過去？** 建議：是。理由見三-7；它管的是人跟手機，不是 AI。
2. **名單只收「綁好 LINE 的成員」，拿掉「從好友清單挑」與「貼 U 開頭 ID」？** 建議：是。挑錯會讓客人收到別的客人的資料（三-3）；正式資料 0 筆會受影響。
3. **客服角色可以自己加進名單、自己退出？** 建議：可以，只能動自己那一列；「什麼時候通知」與動別人仍限管理員。
4. **通知裡放連結？** 建議：放，開到手機的外部瀏覽器。前提是先驗對話頁在手機上能看能回。

## 七、待查證（實作前要做）

- **還不是好友時，「訊息已打好」的連結送不送得出去、送出去之後推播收不收得到。** `member-line-bind.ts:11` 的註解寫「碼是用 LINE 傳進來的＝確實已加好友」，這個前提沒有查證過（`D-101` 選項 B 也留著同一題）。實作時要實測，並用「拿不拿得到他的 LINE 個人資料」之類的方法判斷是不是好友；不是好友就在確認訊息裡附加好友連結（示意頁流程圖 A 的分岔）。
- **對話頁在手機瀏覽器上堪不堪用**（⑦ 的前提）。沒驗過就放連結，等於把人送到一個點不動的頁面。
- 封鎖之後，LINE 對推播回什麼錯誤、要怎麼跟「一時連不上」分開（⑥ 不能把一次網路錯誤當成封鎖）。
