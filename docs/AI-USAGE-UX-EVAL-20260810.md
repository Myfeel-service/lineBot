# 用量監控頁 UI/UX 評估（2026-08-10）

對象：`app/pages/admin/[workspaceId]/ai-usage.vue`（側欄「AI 客服 → 用量監控」）
起因：老闆問「這頁是不是有點像 AI 功能的 dashboard？以 agent 為產品概念的話還能怎麼優化？」

> 這是決策紀錄，寫完凍結。狀態一律看 `docs/STATUS.md`。

---

## 一句話結論

**這頁已經是全站做得最好的一頁之一**（圖表合格、可操作性強、色彩有語意），
**而且它確實應該升格成 AI 的總覽頁**——但升格前有三個結構問題要先解，
否則會出現「最重要的頁面權限最嚴、名字最像計量表」的怪狀。

---

## 一、先回答「該不該當 dashboard」

### 現況：它已經是 dashboard，只是沒被當成 dashboard

側欄 AI 區有四頁：知識庫 / 測試對話 / 用量監控 / AI 設定（另有「自動回應」在上一組）。
**沒有任何一頁是「AI 現在狀況如何」的入口**，而用量監控實際上已經包含了 dashboard 該有的東西：

| Dashboard 該有的 | 這頁有嗎 |
|---|---|
| 系統在不在跑 | ✅ 頂端狀態列（含草稿模式） |
| 核心產出 | ✅ Hero ＋ 三段拆解 |
| 趨勢 | ✅ 近 3 個月柱狀圖 |
| 待辦動作 | ✅ 轉真人案例 ＋ 補知識／開對話／已處理 |
| 額度風險 | ✅ 進度條 ＋ 兩級警示 |

### 但升格前有三個結構問題

**① 權限錯配（最關鍵）**

| 頁面 | capability | 誰看得到 |
|---|---|---|
| 知識庫 | `ai.read` | viewer 起 |
| AI 設定 | `ai.read` | viewer 起 |
| 測試對話 | `playground.use` | agent 起 |
| **用量監控** | **`usage.read`** | **admin 起** |

如果把它升格成 AI 總覽，會變成「最該先看的那頁，權限最嚴」——
**第一線客服（agent）看不到自己照顧的 AI 表現如何**，這跟 agent 產品的邏輯是相反的。

它之所以要 admin，是因為「含計費方案」。而 2026-08-10 已把金額全部移到超管成本總覽，
**現在這頁跟計費有關的只剩「方案額度」那張卡**。這給了一條乾淨的路：
額度卡搬到帳單／設定頁（那裡本來就有方案資訊）→ 這頁不含任何計費 → 權限降到 `ai.read` → 才有資格當總覽。

**② 名字是全頁最術語的地方**

頁面標題「用量 / 監控」聽起來像計量表，但內容其實是「我的 AI 做得好不好、我該補什麼」。
建議改成 **「AI 表現」**（或「AI 總覽」）。這也呼應 2026-08-07 的名詞收斂表——
內文早就白話了，只有頁名還停在工程視角。

**③ 沒有「總覽」該有的收斂**：目前是五張平行卡片，沒有一句「你的 AI 現在算好還是不好」。

## 二、以 agent 為產品概念，這頁該回答三個問題

| 問題 | 現況 | 缺什麼 |
|---|---|---|
| 我的 agent 在做什麼？ | ✅ 狀態列 | — |
| 它做得好不好？ | ⚠️ 有數字沒結論、沒基準 | 見 D、E |
| 我要幫它做什麼？ | ⚠️ 有清單但埋在第四張卡 | 見 G |

**核心建議：Hero 換掉主角。**

現在的 Hero 是「202 則 · 這個月 AI 幫你處理的則數」——那是**用量**視角。
agent 產品賣的是「**幫你擋掉多少**」，所以主角應該是 **自己搞定率**，量退居次要：

```
   68%  自己搞定           ← 主角（現在只是圖例裡的一個小百分比）
   較上月 ▲ 6%             ← 基準（現在完全沒有）
   這個月共 202 則客人訊息   ← 退居副標
```

資料全都現成（`autoReplyRate` 已在回應裡、趨勢 API 已回近 3 個月），是排版問題不是資料問題。

**另一個 agent 化的缺口：看不到「我的 agent 知道什麼」。**
知識卡數、腳本數這些是 agent 的「能力資產」，目前散在知識庫頁與自動回應頁。
總覽頁應該有一張小卡把它們收起來——「它會 X 張知識卡、Y 條自動回應」。

## 三、UI/UX 七維度逐項

### 1. 資料正確（最優先）

**🔴 A. 硬寫「這個月」，但月份可選 → 選上個月就說謊**
三處寫死：Hero 標籤（`則 客人訊息 / 這個月 AI 幫你處理的則數`）、
兩個空狀態（`這個月 AI 還沒有處理任何訊息`、`這個月 AI 還沒有答過題`）。
月份選單有「這個月／上個月／YYYY-MM」。選上個月時這三句全部是錯的。
**修法**：改用既有的 `periodLabel` computed。

**🟡 B. 趨勢圖少一個系列**
Hero 拆三段（自己答完／轉給真人／先問清楚），趨勢圖只畫前兩者。
後果一：兩根柱子加起來 ≠ Hero 總數，會被拿去對帳。
後果二：「先問清楚」偏高代表知識標題太相近（tooltip 自己這樣說），但看不出它在變好還變壞。
**修法**：補第三個 series，色票沿用 `#d99a2b`。

**🟡 C. 移除成本區塊後留下的過期註解**
卡片已刪但註解還在（`<!-- 進階 / 技術細節… -->`）、`advancedOpen` 的註解仍寫「整卡僅 super admin 可見」、
型別區塊留著懸空的 `/** ↓ token / 成本細目 */`。不影響畫面，但會誤導下一個讀 code 的人。

### 2. 第一次看就懂

**🔴 D. 沒有任何「跟上期比」**
Hero 是一個孤立的數字。202 則是多還少？沒有基準就不叫監控，叫快照。
資料現成（趨勢 API 已回近 3 個月），加一個「較上月 ▲38%」即可。

**🟠 E. 沒有結論**
房規：狀態面板要「結論先行」。頂端狀態列只講「有沒有開」，沒講「做得好不好」。
建議在狀態列或 Hero 下方加一句由真實數字推出的判語，例如
「自己搞定率 68%，比上月進步；有 12 個問題還沒補知識」。

### 3. 反術語白話
✅ 通過。「自己答完／轉給真人／先問清楚」已經過名詞收斂，兩本帳（則 vs 場）也有 tooltip 說明。
唯一術語殘留是頁名本身（見 ②）。

### 4. 對齊 / 整齊

**🟡 F. `usage-substats` 現在只剩一格**
移除成本區塊後，這個 `grid-template-columns: repeat(auto-fit, minmax(200px,1fr))` 容器只剩一個子元素，
會撐滿整行——一個小數字上面壓一條全寬分隔線，看起來像沒做完。
**修法**：把「答完客人又找真人」併進 Hero 區當第二個指標，或讓容器在單一子元素時不畫上緣線。

### 5. 圖表能直接讀數
✅ **通過，而且是全站標竿**：有 Y 軸、虛線格線、hover tooltip、柱上直接標值、
`minInterval:1` 避免小數刻度、`max` 留 15% 頂空避免標籤被切。
色票與 Hero 同源並留了「改 token 要回來改這裡」的註解防漂移。

### 6. 可操作性
✅ 大致通過，也是全站標竿：Hero 的「轉給真人」可點下鑽、
轉真人案例每列有補知識／開對話／已處理、
空狀態寫成「沒有待補知識的轉真人對話了 ✓」而不是死的「無資料」、
傳圖案例刻意不給「補知識」（那會拿「[圖片]」當卡片標題，是死路）。

**🟠 G. 但最有價值的動作埋在第四張卡**
順序是 狀態 → 額度 → 核心指標 → 趨勢 → 待補知識。
以 agent 產品來說「我該做什麼」應該更靠前，建議移到趨勢之前。

### 7. 色彩語意
✅ 通過。三段色各有語意（綠＝自己搞定、藍灰＝轉人、琥珀＝要留意），
趨勢圖與 Hero 同色且有防漂移註解，額度進度條依門檻變色（共用 `derivePlanState`）。

## 四、建議執行順序

| 順序 | 項目 | 理由 |
|---|---|---|
| 1 | A：「這個月」改用 `periodLabel` | 資料正確優先，且是純文字修改 |
| 2 | C：清掉過期註解 | 順手，避免誤導 |
| 3 | F：單格排版 | 上一輪改動造成的，該收尾 |
| 4 | D：Hero 加「較上月」 | 資料現成，投報率最高 |
| 5 | B：趨勢補第三系列 | 讓兩處對得起來 |
| 6 | G：待補知識清單上移 | 純排序 |
| 7 | Hero 換主角（自己搞定率） | 產品定位調整，需拍板 |
| 8 | 額度卡搬走 → 降權限 → 改名 | 結構調整，牽動側欄與 capability，需拍板 |

1～6 是修繕，7～8 是產品決定。
